# OA V1.0 开发计划

## 1. 迭代顺序

### Iteration 0：工程准备

项目骨架、代码规范、CI、环境配置、数据库迁移、日志、监控、错误处理和基础部署。

### Iteration 1：平台底座

租户、登录、用户、组织、岗位、角色、菜单/操作/API/数据权限、字典、文件和审计。

### Iteration 2：流程与表单

表单定义、流程设计、版本发布、条件路由、审批任务、会签、驳回、撤回、转办、委托、抄送和通知。

### Iteration 3：请假与出差

用请假验证简单状态机、工作日算法和余额；用出差验证日期、同行人、标准和后续报销关联。

### Iteration 4：报销与采购

费用明细、发票、预算、金额路由、借款冲销、付款状态、采购目录和供应商基础资料。

### Iteration 5：合同、知识和工作台

合同台账、到期提醒、文件版本、制度发布、角色化工作台、待办聚合和基础报表。

### Iteration 6：集成与发布

移动审批、企业微信/钉钉适配、导入导出、性能、安全、备份恢复、灰度和上线验收。

## 2. 每个迭代的完成定义

需求编号已确认；页面、API、数据和验收文档已同步；代码通过单元和集成测试；关键流程完成端到端测试；权限、审计和错误处理已验证；部署和回滚步骤已演练。

## 3. 不应提前承诺的内容

在组织权限、流程引擎、请假和报销未稳定前，不应承诺完整 HR、ERP、CRM、复杂 BI、AI 问数或大规模第三方集成。

## 4. 立项前决策清单

- 首发用户规模、租户模式和部署方式。
- 技术栈、数据库、对象存储、缓存和消息组件。
- 首发移动端渠道及企业微信/钉钉优先级。
- 请假、报销、采购和合同的业务规则负责人。
- 数据保留、备份恢复、合规和安全验收负责人。
