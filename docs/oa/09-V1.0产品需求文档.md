# 中小企业 OA V1.0 产品需求文档

## 1. 文档目的与范围

本 PRD 是 V1.0 的产品开发基线，定义通用交互、权限、流程和首批业务的共同约束。具体业务规则以请假、报销、出差、人事档案与考勤模块 PRD 为准。

当前已实现范围：登录认证、组织与权限、工作台、流程中心、文件与消息，以及请假、报销、出差、人事档案、基础考勤和劳动合同台账/到期预警。采购已完成 PRD 但按人力资源优先级暂缓；入离职办理清单和招聘为下一阶段。

## 2. 角色与权限

| 角色 | 主要权限 |
|---|---|
| 员工 | 查看自己的数据，创建/提交/撤回自己的单据，处理分配给自己的任务 |
| 部门负责人 | 审批其职责范围内的流程，查看本部门及下级部门授权数据 |
| 财务专员 | 审批费用单据，确认付款，查看授权范围的费用数据 |
| 财务经理 | 审批费用单据，维护费用和预算规则 |
| HR/行政 | 维护人事档案、考勤班次与记录、假期和工作日历及行政数据 |
| 系统管理员 | 维护用户、组织、角色、流程、字典和系统参数 |

角色不等于数据范围。每次详情、列表、导出、下载和操作都必须由服务端执行资源权限与数据范围校验。

具有 `USER_MANAGE` 的管理员可维护角色名称、操作权限和请假/报销/出差/人事/考勤独立数据范围，也可新增自定义角色。范围支持仅本人、本部门、本部门及下级部门、全公司；跨用户范围必须同时选择对应范围查看权限。系统预置角色不可删除；已分配用户的自定义角色必须先解除分配才可删除。管理员不得移除自己最后一份用户管理权限，权限或数据范围变化后受影响用户的既有会话立即失效。

## 3. 全局业务规则

### 3.1 身份与组织

- 仅状态为 `ACTIVE` 的用户可登录、发起申请和处理待办。
- 用户账号、组织关系、角色和权限必须持久化；密码不得明文或可逆保存。连续 5 次密码错误后锁定 15 分钟，管理员重置临时密码可解除锁定、撤销会话，并要求目标用户下次登录设置正式强密码。
- 登录成功后由服务端签发短期访问令牌和 HttpOnly 刷新 Cookie；访问令牌仅驻页面内存，刷新页面通过轮换 Cookie 恢复有效会话。
- 退出登录必须撤销服务端会话并清除 Cookie；密码重置、停用账号或调整安全角色同样撤销既有会话。任何受保护路由和 API 均不得信任客户端传入的用户或租户标识。
- 发起人默认使用其主部门；兼任部门只能在获授权时选择。
- 用户、部门或审批关系在单据提交后发生变化，不回写历史单据快照；正在运行的流程按流程配置决定是否重新解析未创建节点的审批人。

### 3.2 编号与时间

- 每类业务单据按租户唯一编号生成；格式由租户参数配置，默认示例：`BX-YYYYMMDD-000001`。
- 所有业务时间使用租户时区展示；服务端存储 UTC 时间。
- 金额使用两位小数的十进制定点数，禁止浮点运算。

### 3.3 附件与文件

- 单文件最大 20MB；允许 PDF、JPG、JPEG、PNG、XLS、XLSX、DOC、DOCX。
- 上传后执行类型、大小和安全校验；未通过校验的文件不可关联单据。
- 文件访问同时校验租户、单据数据权限和文件权限；下载、预览与删除均记审计日志。

### 3.4 提交与并发

- 所有提交、审批、撤回、付款等写操作必须幂等；客户端每次首次动作提供 `Idempotency-Key`。
- 单据更新携带版本号；版本不匹配时提示“单据已被更新，请刷新后重试”。
- 单据提交成功的最低一致性标准是：单据状态、流程实例、当前待办和审计日志同时落库。

## 5. 通用页面行为

### 5.1 工作台

展示待我审批、待我阅读、我发起的进行中事项、常用入口和公告。每个待办显示业务类型、编号、标题、发起人、发起时间、当前节点和紧急标记；点击进入详情。

工作台“最新公告”展示最近发布的 3 条有效公告，标记当前用户“待确认/已读”，点击进入详情。公司公告列表使用服务端分页并按发布时间倒序；详情保留正文换行、发布人、发布时间和有效期，员工可执行一次“确认已读”，重复操作不产生重复记录。

具有 `ANNOUNCEMENT_MANAGE` 权限的 HR/行政或系统管理员可创建公告草稿、编辑草稿、发布和撤回。发布后正文不可覆盖；需要修正时撤回并新建公告。撤回或过期后普通员工立即不可见，但管理员和审计日志仍可追溯。所有状态操作使用系统内确认弹窗并携带版本号。

### 5.1.1 组织通讯录

展示部门、员工姓名、岗位/主角色和直属上级，支持按部门以及姓名、岗位、上级关键字筛选。普通用户仅可读取 ACTIVE 员工目录，不暴露社会工龄、账号状态、完整角色权限或密码信息。

### 5.1.2 用户与权限

具有 `USER_MANAGE` 权限的用户可按姓名/用户 ID、状态和部门筛选用户，列表由数据库分页并按创建时间倒序。可新建账号，维护姓名、部门、直属上级、社会工龄、启停状态和一个或多个角色，也可重置临时密码。用户 ID 创建后不可修改；管理员分配的临时密码和用户设置的正式密码均须为 12–128 位并包含大小写字母、数字和特殊字符，正式密码还不得复用临时密码。用户首次登录必须在不签发业务会话的前提下完成修改。系统必须阻止管理员停用自己或移除自身用户管理权限，所有用户与密码管理动作均写审计日志。

### 5.1.2.1 组织架构维护

具有 `ORG_MANAGE` 权限的用户可在树形表格中查看部门编码、名称、上级、层级、排序、用户数、下级数和系统标记，并新建下级部门或编辑名称、上级和排序。部门编码创建后不可修改；系统预置部门不可删除，自定义部门只有在没有下级且没有用户时才可删除。页面须排除自身及其下级作为可选父部门，服务端仍需独立校验循环和最多 8 层限制。层级移动成功后提示现有登录会话会失效，并由系统要求重新登录。

### 5.1.2.2 岗位管理

具有 `ORG_MANAGE` 权限的用户可按部门筛选岗位，查看岗位编码、名称、所属部门、用户数、排序、状态、类型和版本，并新增或编辑岗位。岗位编码创建后不可修改；岗位只描述组织职责，不授予权限。系统预置岗位不可删除，已分配岗位不可移动、停用或删除。用户管理页分别展示并编辑主岗位与安全角色，主岗位只能选择所属部门下的启用岗位；未分配岗位时通讯录显示“未分配”，安全角色继续单独展示。

### 5.1.3 登录设备

所有已登录用户可查看自己的登录设备，列表展示设备摘要、网络地址、登录时间、最近使用时间、有效期、状态和当前设备标识，并按最近使用时间倒序分页。用户可撤销任一其他有效会话或一次性退出全部其他设备；当前设备只能通过页头“退出”操作撤销，避免误操作导致当前页面突然失效。

### 5.1.4 角色与权限

管理员可查看系统和自定义角色、已分配用户数、请假/报销/出差/人事/考勤数据范围及权限摘要。新增角色需填写不可变编码、显示名称、各业务数据范围和权限集合；编辑时可调整名称、范围和权限。系统角色保留“不可删除”属性，自定义角色在用户数为 0 时才显示可用删除操作。创建、更新和删除均写审计日志；普通员工直接访问页面或 API 均被拒绝。

### 5.1.5 人事档案与考勤

员工花名册由账号、部门、岗位、直属上级和人事档案共同构成。员工查看本人，上级查看管理链下属，HR/行政按 `Personnel` 范围维护工作联系方式、用工状态和入转调离日期；变更形成只追加事件，离职办结同步停用账号并撤销会话。

考勤管理与工作日历分离。工作日历定义日期是否工作，考勤记录保存员工当天班次快照、原始打卡、异常状态和来源。HR 可维护默认班次、录入记录或幂等补齐模拟数据；员工可对本人异常提交申诉，HR 审核通过后保留原始异常并标记已修正。列表服务端分页、新记录在前，月度汇总与明细使用同一 `Attendance` 数据范围。HR 在待审申诉清零后可封账月份，封账后历史考勤只读；解封必须记录原因并通过版本并发校验。

### 5.2 列表页

- 默认仅展示当前用户有数据权限的记录，按最近更新时间倒序。
- 支持关键字、状态、发起人、所属部门和日期区间筛选；报销额外支持金额区间。
- 空状态说明无数据原因，并提供有权限时的“新建”入口。
- 导出仅导出当前筛选条件、当前数据权限内的字段；导出为异步任务并保留审计。

### 5.3 详情页和审批抽屉

详情由单据内容、附件、审批时间线和操作区组成。审批操作至少包含同意、驳回、转办和查看历史；同意、驳回和转办使用系统内弹窗，不依赖浏览器原生输入框。驳回、转办必须填写意见，转办人从同租户 ACTIVE 用户中选择。执行操作前需再次拉取单据状态，避免对已处理任务重复操作；提交期间禁用关闭和重复提交。

### 5.4 审计日志

仅系统管理员可查看。列表默认按发生时间倒序，支持按动作/摘要/资源 ID 关键字、操作人、资源类型和日期区间筛选，并使用服务端分页。服务端必须独立执行角色校验，普通用户即使直接调用接口也返回 `AUTH_002`。

### 5.5 流程定义与版本

系统管理员可查看请假和报销的全部流程版本，从历史版本复制新草稿，编辑优先级、适用部门、适用假别、条件上限和顺序审批节点，再发布为当前版本。部门不选表示全公司，选择部门时包含其下级部门；请假假别不选表示全部假别，报销流程不显示假别范围。流程列表按创建时间倒序分页展示。

新单据在已发布流程中依次按优先级、范围具体度、版本和发布时间匹配。不同流程编码在同业务类型下不得以相同优先级、相同具体度发布相交范围，否则提示范围冲突。已发布和已归档版本不可直接修改；同一流程编码仅有一个当前发布版本。单据提交时绑定当时的流程 ID、编码和版本，发布新版本或新的范围流程不得改变运行中及历史单据的任务。

### 5.6 审批委托

用户可选择在未来或当前生效的起止时间、业务范围（全部、请假、报销）、代办人和原因创建委托。代办人必须为其他 ACTIVE 用户；同一时间和相交业务范围内只允许一条有效委托。新待办创建时将任务分配给代办人，同时在轨迹中保留原审批人和委托来源；一个人因委托同时命中连续节点时自动去重。取消委托不回收已创建待办，只影响此后生成的任务。

### 5.7 流程实例与审批轨迹

单据每次提交均创建独立流程实例并绑定当时的流程定义版本，提交次数从 1 递增。实例状态包括审批中、已完成、已驳回和已撤回；提交、同意、驳回、转办和撤回均形成不可覆盖的动作记录，保存操作者、时间、节点、意见及转办双方。驳回后修改并重提必须创建新实例，详情按新到旧展示全部实例，旧实例及意见永久保留。

顺序流程仅将当前最小未处理节点暴露为待办，未来节点不可提前处理或提前通知；当前节点通过后才激活下一节点。任一节点驳回时，当前实例终止并取消其余未处理任务。实例查询必须复用关联单据的数据权限。

### 5.8 流程抄送与待我阅读

请假和报销发起人可选择最多 20 名同租户 ACTIVE 用户作为抄送人，不允许选择自己，重复用户自动去重。草稿和审批中单据不向抄送人暴露；流程审批完成或申请撤回后，系统激活抄送关系、发送站内通知，并授予抄送人对该单据及附件的只读权限。

“待我阅读”独立于普通通知，按抄送生效时间倒序分页，展示未读/已读、业务单号、标题、发起人、结果和时间。只有抄送人本人可以标记已阅；阅读后未读统计即时减少。驳回但尚可修改重提的单据不激活抄送，发起人可在重提前调整抄送人。

## 6. 通知规则

| 触发事件 | 收件人 | 通知内容 |
|---|---|---|
| 提交成功 | 发起人 | 单据已提交、当前审批节点 |
| 创建待办 | 审批人 | 业务类型、发起人、摘要、待办链接 |
| 审批通过/驳回 | 发起人 | 处理结果、意见、下一节点或可编辑提示 |
| 流程完成 | 发起人、抄送人 | 最终结果和详情链接 |
| 即将超时/已超时 | 当前审批人、按配置抄送人 | 业务摘要、时限和链接 |

站内信为必选渠道；企业微信、钉钉和邮件作为可配置扩展。消息投递失败可重试，不能回滚已成功的业务事务。

## 7. 通用验收标准

- AC-GEN-000：有效 ACTIVE 账号可登录并在刷新后恢复会话；错误密码、停用账号、无令牌和篡改令牌均不能访问受保护资源。
- AC-GEN-001：无菜单权限或无数据权限的用户不能通过直接访问 URL、API 参数或文件 URL 访问资源。
- AC-GEN-002：单据提交、审批、撤回重复请求时，系统只执行一次有效状态迁移，并返回同一结果或明确的状态错误。
- AC-GEN-003：所有单据状态变更都在详情时间线和审计日志中保留操作者、时间、动作、意见与请求标识。
- AC-GEN-004：审批人处理完成后，待办从该审批人列表移除；下一审批人及时收到待办和通知。
- AC-GEN-005：流程定义发布新版本后，已有流程实例继续使用原版本，新发起单据使用新版本。
- AC-GEN-006：研发部病假同时命中公司级和研发级流程时选择更高优先级流程；财务部病假可命中包含下级部门的公司级流程；同优先级重叠范围不能发布。
