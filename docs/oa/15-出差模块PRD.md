# 出差模块 PRD

## 1. 目标与范围

出差模块用于员工提交境内出差申请，验证多段行程、同行人、按日历天数审批路由以及审批通过后关联报销的完整闭环。V1.0 Web 端支持响应式手机布局，不包含机票酒店预订、借款、差旅标准自动核销和出差变更单；这些能力保留为后续配置模块。

## 2. 角色与数据权限

- 员工：创建、查看本人出差；在首个审批节点处理前撤回。
- 直属上级：查看并审批直接及间接下级出差。
- 总经理：处理超过 3 个日历天的第二级审批。
- 抄送人：仅在审批完成或撤回后获得只读详情及附件权限。
- 配置了 `TRAVEL_SCOPE_VIEW` 的角色：按 `SELF`、`DEPARTMENT`、`DEPARTMENT_AND_CHILDREN`、`COMPANY` 查看出差。
- 系统管理员：默认具有全公司出差数据范围，并可维护 Travel 流程定义。

## 3. 页面与入口

| 路径 | 页面 | 主要能力 |
|---|---|---|
| `/travel` | 出差管理 | 服务端筛选、分页、最新在前、新建表单 |
| `/travel/{id}` | 出差详情 | 基本信息、行程、同行人、附件、任务和永久流程轨迹 |
| `/approval` | 审批中心 | 出差待办、同意、驳回、转办、已办 |
| `/expense` | 费用报销 | 可选择本人已批准的出差作为来源 |

## 4. 字段规格

### 4.1 出差主单

| 字段 | 规则 |
|---|---|
| 出差事由 | 必填，1–500 字 |
| 预估预算 | 必填，0–10,000,000 元，最多两位小数；仅作申请说明，不作为法定标准 |
| 行程明细 | 必填 1–20 条 |
| 同行人 | 可选，最多 20 名 ACTIVE 用户，不得包含申请人，自动去重 |
| 附件 | 可选，使用统一文件白名单和 20MB 限制，必须归当前上传人所有 |
| 抄送人 | 可选，最多 20 名 ACTIVE 用户，不得包含申请人 |

### 4.2 行程明细

| 字段 | 规则 |
|---|---|
| 目的地 | 必填，1–100 字 |
| 开始/结束日期 | 必填，结束不得早于开始；各段不能重叠 |
| 交通方式 | 必填，最长 32 字；前端提供高铁、飞机、汽车、自驾、轮船、其他 |
| 行程任务 | 必填，1–300 字 |

整单开始和结束日期取所有行程的最小/最大日期；时长按首尾日期包含计算的日历天数，单次跨度不超过 180 天。

## 5. 状态机与操作

```text
DRAFT ─提交→ APPROVING ─全部通过→ APPROVED
   │                  ├─驳回→ REJECTED ─修改重提→ APPROVING
   └─删除             └─首节点未处理时撤回→ WITHDRAWN
```

- `DRAFT`、`REJECTED` 可编辑；`DRAFT`、`REJECTED`、`WITHDRAWN` 可删除。
- `APPROVING` 只有全部任务仍为待处理时可撤回。
- 驳回取消同一实例后续任务，修改重提创建新流程实例并保留旧轨迹。
- 同一申请人不能提交与审批中或已批准出差日期重叠的申请。

## 6. 审批路由

默认 `TRAVEL_DEFAULT` 流程按出差日历天数路由：

- `≤ 3 天`：直属上级。
- `> 3 天`：直属上级 → 总经理。

系统管理员可复制默认流程，设置部门范围、优先级和条件阈值后发布；已发布版本不可直接修改，既有单据继续绑定提交时版本。

## 7. 报销衔接

- 报销创建请求可传可空 `travelRequestId`。
- 服务端只接受“当前报销申请人本人 + 状态为 APPROVED”的出差。
- 未批准、已驳回、已撤回、他人或不存在的出差返回 `TRAVEL_004`。
- 一个出差可关联多张报销单，以支持分批或不同费用类别核销；报销详情显示出差编号并可回跳。
- V1.0 不自动比较预估预算与实报金额，不自动套用住宿、交通或补贴标准；后续由可配置差旅标准模块补充。

## 8. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/v1/travel-requests` | 分页查询/创建草稿 |
| GET/PATCH/DELETE | `/api/v1/travel-requests/{id}` | 详情/按版本编辑/删除 |
| POST | `/api/v1/travel-requests/{id}/submit` | 提交审批 |
| POST | `/api/v1/travel-requests/{id}/withdraw` | 未处理时撤回 |
| GET | `/api/v1/travel-tasks/my` | 我的出差待办 |
| GET | `/api/v1/travel-tasks/done` | 我的出差已办 |
| POST | `/api/v1/travel-tasks/{id}/{approve|reject|transfer}` | 审批动作 |

## 9. 验收标准

- **AC-TRAVEL-001**：创建 2 天出差并提交，只生成直属上级任务。
- **AC-TRAVEL-002**：创建 4 天出差并提交，顺序生成直属上级和总经理任务，后序任务在前序通过前不可见。
- **AC-TRAVEL-003**：同行人不存在、停用、包含本人或超过 20 人时拒绝保存。
- **AC-TRAVEL-004**：多段行程日期重叠或整单超过 180 天时拒绝保存。
- **AC-TRAVEL-005**：与本人审批中/已批准出差日期重叠时拒绝提交。
- **AC-TRAVEL-006**：首节点未处理可撤回，已有节点处理后不能撤回。
- **AC-TRAVEL-007**：审批完成后抄送人获得只读权限，其他无范围用户不能读取。
- **AC-TRAVEL-008**：报销可关联本人已批准出差；关联其他状态或他人出差返回 `TRAVEL_004`。
- **AC-TRAVEL-009**：列表使用服务端分页并按创建时间倒序，手机宽度无页面级横向溢出。
- **AC-TRAVEL-010**：关键创建、提交、审批、驳回、转办、撤回和删除动作写入审计。
