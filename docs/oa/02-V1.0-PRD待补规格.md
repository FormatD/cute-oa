# OA V1.0 PRD 待补规格

本清单用于把总体设计升级为开发和测试共同使用的需求基准。每项完成后应有唯一编号，并关联页面、接口、数据表和验收用例。

## 1. 功能规格模板

每个需求至少补齐：

- 需求编号、名称、优先级、使用角色
- 前置条件和权限
- 页面路径、入口和页面状态
- 输入字段：类型、必填、默认值、枚举来源、长度和格式
- 用户操作及按钮权限
- 提交流程、业务规则和状态变化
- 接口、错误码、通知和审计记录
- 空状态、加载失败、重复提交、并发修改和回滚处理
- Given/When/Then 验收标准

## 2. 首批重点规格

### FR-LEAVE：请假

需要明确：假别、余额、工作日算法、节假日、半天/小时假、跨日、撤回、驳回修改、销假和余额恢复。

### FR-TRAVEL：出差

需要明确：出差地点和时间、同行人、差旅标准、借款衔接、变更/取消、与报销单关联。

### FR-FIN：报销

需要明确：费用明细、发票条件、金额精度、预算校验、审批金额路由、借款冲销、付款、批量导入、重复发票和附件安全。

### FR-PROC：采购申请

已在《16-采购申请模块PRD》中明确 V1.0 的多明细、金额分级审批、报价附件、下单登记、验收闭环、权限、接口和异常用例。采购目录、供应商准入与评分、预算余额、招投标、库存、付款和合同关系保留为后续模块。

### FR-CONTRACT：合同/用章

需要明确：合同编号、版本、法务/财务审核、印章、电子签、履约、付款/收款、到期提醒和归档权限。

## 3. 必须形成的配套文档

| 文档 | 最低内容 |
|---|---|
| 页面详细设计 | 页面区域、字段、按钮、权限、空/错/加载状态 |
| 业务流程与状态机 | 节点、路由、状态、允许操作、异常转移 |
| 数据库设计 | ER、表字段、约束、索引、审计和租户隔离 |
| API 设计 | 请求/响应、分页、错误码、幂等、鉴权和版本 |
| 消息通知设计 | 触发条件、渠道、模板、重试、已读和免打扰 |
| 安全与审计 | 登录、密码、文件、敏感字段、操作日志、备份恢复 |
| 测试与验收 | 正常、权限、边界、异常、并发和回归场景 |

## 4. 示例验收标准

**AC-FIN-001**：用户具有有效报销权限，创建金额为 8,650 元的报销并提交后，系统生成唯一编号，状态进入审批中，创建流程实例和首个待办，并向审批人发送通知。

**AC-FIN-002**：报销金额超过 5,000 元时，部门经理和财务审批完成后，系统自动生成总经理审批任务；金额低于或等于阈值时不得生成该任务。

**AC-FIN-003**：审批人驳回后，报销状态变为已驳回，申请人收到通知；申请人可按规则修改后重新提交，历史审批轨迹保留。

## 5. 完成定义

某个业务模块只有同时具备“需求编号、页面规格、业务规则、状态机、接口、数据定义、异常处理和验收用例”，才可标记为可开发/可测试；仅有菜单或功能名称时，标记为规划中。
