# OA 实施差距与下一迭代

## 1. 本轮结论

当前系统已经形成“持久化账号与权限、组织架构、登录会话、请假、报销、审批、通知、付款、工作日历、附件、审计，以及人事档案、考勤、劳动合同”的业务闭环。账号密码以随机盐 PBKDF2 保存并支持失败锁定、管理员重置；短期 JWT 绑定持久化会话，刷新令牌使用 HttpOnly Cookie、摘要存储和轮换。受保护接口从数据库解析最新用户状态、权限和会话状态，不再信任客户端身份。前端具备登录、刷新恢复、自动续期、退出、登录设备、权限菜单/路由、用户、角色、部门树及人力资源管理页面；关键操作使用响应式系统弹窗，不再依赖浏览器原生输入框。

附件服务当前使用应用本地磁盘保存二进制文件，并持久化文件元数据；上传采用白名单与 20MB 限制，先写隔离文件并通过 ClamAV INSTREAM 扫描，感染或扫描异常均失败关闭，下载仍须通过关联单据的数据权限校验。单节点持久卷可作为生产候选，但仍不等同于共享对象存储、在线预览和完整生命周期管理。

## 3. 下一迭代优先级

### P0：权限配置与认证增强

在已落地的持久化用户、部门树、单一主岗位、账号、角色定义与权限、请假/报销角色数据范围、刷新轮换和会话撤销基础上，补充兼任组织/多岗位、MFA/IP 限流、多租户上下文、字段权限和指定组织范围。

### P0：文件服务与权限底座

抽象对象存储适配，补充目录/版本、预览、孤儿文件清理和生命周期策略；在预发布环境完成真实 ClamAV/EICAR 联调，保留现有文件 ID 与单据权限下载协议。

### P1：流程中心能力

在现有流程定义版本、部门/假别适用范围、独立流程实例、审批委托和抄送基础上，继续加入会签、加签和审批 SLA；已有单据及实例继续绑定旧版本。

### P0：人力资源上线门禁

人事档案、员工生命周期办理清单、考勤和劳动合同已完成单节点生产候选实现；应用内附件扫描与失败关闭已落地，下一步先执行生产密钥、TLS、附件持久卷和真实 ClamAV/EICAR 联调、备份恢复、外部监控及真实角色验收，再建设招聘录用转入职和更细的跨部门任务角色。考勤已具备不可变封账月报版本、完整性校验和受审计下载，后续再扩展员工班次分配、排班、外部打卡接入、员工电子签字确认和薪资批次关联。

### P2：新增业务模块

出差、劳动合同和采购申请模块均已闭环；用章申请模块排在采购之后，下一步应建立详细 PRD 并推进全链路研发。

## 4. 下一次开发的验收门槛

- 文件上传、下载和越权访问分别有 API 与集成测试；
- 单据附件在详情、审计和删除策略中可追溯；
- 不把开发签名密钥、模拟账号密码或当前缺少 MFA/限流的认证实现当作生产认证方案；
- 新业务模块先完成 PRD、数据模型、接口和异常用例，才进入页面开发。
