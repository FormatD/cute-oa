# OA 实施差距与下一迭代

## 1. 本轮结论

当前系统已经形成“持久化账号与权限、组织架构、登录会话、请假、报销、审批、通知、付款、工作日历、附件、审计，以及人事档案、考勤、劳动合同、用章管理、企业知识库与制度中心”的业务闭环。账号密码以随机盐 PBKDF2 保存并支持失败锁定、管理员重置；短期 JWT 绑定持久化会话，刷新令牌使用 HttpOnly Cookie、摘要存储和轮换。受保护接口从数据库解析最新用户状态、权限和会话状态，不再信任客户端身份。前端具备登录、刷新恢复、自动续期、退出、登录设备、权限菜单/路由、用户、角色、部门树、知识库制度及人力资源管理页面；关键操作使用响应式系统弹窗，不再依赖浏览器原生输入框。

附件服务当前使用应用本地磁盘保存二进制文件，并持久化文件元数据；上传采用白名单与 20MB 限制，先写隔离文件并通过 ClamAV INSTREAM 扫描，感染或扫描异常均失败关闭，下载仍须通过关联单据的数据权限校验。单节点持久卷可作为生产候选，但仍不等同于共享对象存储、在线预览和完整生命周期管理。

## 3. 下一阶段目标

下一阶段定义为 **V1.0 功能收口与发布候选阶段**。目标不是继续堆叠孤立模块，而是把当前已经实现的业务连接成员工、管理者、HR、财务和行政每天都能连续使用的 OA 工作闭环。

阶段成功标准：用户从统一入口看到所有待处理事项；业务规则可由管理员维护而不是依赖代码常量；管理层能够看到审批、费用、考勤、合同和制度执行情况；核心流程可在响应式 Web 端完整办理并形成可追溯记录。

## 4. 功能建设优先级

### P0-F1：统一工作台与事项中心（已完成）

已建立统一任务模型和 `/work-items` 聚合接口，原按业务模块分区的审批中心已升级为事项中心。聚合接口只调用各业务已授权查询或复用相同数据范围规则，顺序审批仍只暴露当前节点；普通员工不能通过摘要或风险页签获知权限范围外的数据。

当前实现包括：

- 提供“待我处理、我的已办、我发起的、待我阅读、风险提醒”五个页签；
- 聚合请假、报销、出差、采购、用章审批，以及员工办理任务、考勤申诉、合同预警、公告阅读和制度签收；
- 每条事项统一展示业务类型、编号、标题、发起人、当前节点、到达时间、截止时间、紧急程度和状态；
- 支持业务类型、状态、发起人、部门、日期和关键字筛选，使用服务端分页并按“已逾期、即将到期、最新到达”排序；
- 工作台按角色展示不同卡片：员工看个人事项，负责人看团队待办，HR 看人事/考勤/合同风险，财务看待付款与费用，管理员看授权范围内的跨业务概览；系统运行风险由后续运维监控承载；
- 移动宽度下支持查看详情和单条审批，驳回、转办仍必须填写意见；高风险动作不提供无详情批量审批。

验收结果：员工提交请假、主管从事项中心审批并在已办查询的核心浏览器链路已自动化通过；员工合同风险越权隔离、聚合分页、制度版本升级后重新待签收已通过 PostgreSQL 回归。P0-F2 已补全审批事项截止时间、紧急程度与逾期优先排序。

### P0-F2：流程时效、催办与异常路由（已完成）

在现有串行节点、条件路由、版本发布、转办、委托和抄送基础上，已交付以下流程运营能力：

- 每个审批节点可配置办理时限、提醒提前量、逾期升级时间/对象、审批人缺失策略及连续重复节点是否允许自动跳过；
- 到期前发送站内提醒，逾期后标记并按配置升级给直属上级或流程管理员；
- 审批人停用、离职、无有效上级或连续节点命中同一人时，按配置给出流程管理员替补、跳过或阻断结果；存在活动审批任务的账号不能直接停用或办结离职；
- 流程发布前提供模拟试算，输入申请人、部门、业务金额或天数即可预览命中的流程版本和审批人；
- P1 再加入会签、或签和前/后加签，历史实例继续绑定提交时的流程版本。

验收结果：节点配置与流程试算已有浏览器端到端用例；SLA 快照、顺序节点独立起算、临期/逾期/升级接收人、重复扫描去重、异常路由、停用门禁、驳回取消和下一节点激活均已通过 PostgreSQL 回归。运行实例保存提交时策略快照，流程新版本不改写既有实例。

### P0-F3：业务参数配置中心（已完成）

将当前分散在代码、演示数据或部署配置中的业务规则逐步转为有权限、有版本、有生效日期的管理配置：

- 假勤：假别启停、最小申请单位、证明附件门槛、企业年假上浮规则、调休有效期；法定最低标准不可被配置降低；
- 费用与出差：费用类别、单项限额、城市/职级差旅标准、超标说明和发票必填规则；
- 采购：采购类别、报价附件门槛、金额分级、采购负责人和验收要求；
- 用章：印章台账、印章管理员、文件类别、外带规则、归还期限和风险等级；
- 系统字典：合同类型、附件类型、常用审批意见字典等。

配置修改必须写审计并形成版本；新申请使用生效中的版本，历史单据保留原规则快照。系统拒绝删除已被业务数据引用的配置。

验收结果：假勤、费用、差旅、采购、印章、业务字典全域参数管理已落地；支持版本发布、生效中/待生效/草稿/已下线状态机、历史单据快照冻结追溯与禁止删除已引用规则；前端支持结构化 UI 回显与原始 JSON 快照双模式无缝切换；PostgreSQL 集成测试及 Playwright 全量浏览器端到端用例均已回归通过。详见 [27-业务参数配置中心PRD](./27-业务参数配置中心PRD.md)。

### P1-F4：费用、预算与采购付款闭环

在现有报销付款、出差关联报销和采购下单/验收基础上继续补齐财务协同：

- 报销增加发票类型、发票号码、开票日期、含税金额和重复发票提示；首发不接入税务验真；
- 建立部门/项目/费用科目的月度或年度预算，提交时提示预算占用和超额情况；
- 区分“审批通过、待付款、部分付款、已付款、付款失败”，允许财务登记多次付款流水；
- 采购申请关联采购订单、到货验收、发票和付款状态，形成申请金额、下单金额、验收金额和付款金额对照；
- 财务按权限导出当前筛选结果，所有导出和付款动作写审计。

验收标准：预算占用、释放和实际发生金额可对账；撤回、驳回、订单取消和付款失败不会留下错误占用；财务全公司报销权限不外溢到人事和合同。

### P1-F5：管理驾驶舱与业务报表

建立服务端统计接口和角色化驾驶舱：

- 审批：提交量、通过率、平均/P95 时长、逾期数量、节点瓶颈；
- 费用与采购：部门趋势、费用类别、预算执行、采购金额和待付款；
- 人力：在职人数、入转调离、年假使用、考勤异常、合同到期；
- 行政与合规：用章数量、外带未归还、公告阅读率、制度签收率；
- 指标支持日期和部门筛选，统计结果继续受角色和数据范围控制。

验收标准：报表汇总值可追溯到权限范围内的明细；普通负责人只能看到管理链范围，财务和 HR 只能看到各自授权领域。

### P1-F6：知识库与文件体验增强

- 为 PDF、图片和浏览器可安全展示的文本提供在线预览，其他格式保持受控下载；
- 增加制度失效提醒、待签收催办和负责人团队签收进度；
- 增加附件版本、替换原因和孤儿文件清理策略；
- 优化标题、正文、标签和文号搜索，保留后续接入独立全文检索服务的边界；
- 单节点上线继续使用加密持久卷；需要多实例时再切换共享对象存储。

### P1-F7：人事与考勤运营增强

- 支持员工班次分配、周期排班、临时调班和排班发布；
- 提供标准考勤导入模板、导入预检、错误行下载和重复记录处理；
- 增加员工月度考勤确认，封账前展示待确认和争议状态；
- 输出受权限控制的薪资核算输入批次，但不在 OA 内计算工资、个税和社保；
- 兼任岗位、跨部门职责和招聘转入职放入后续需求评审，不阻塞当前单主岗位版本上线。

### P2：扩展业务模块

资产管理、办公用品领用、会议室、车辆调度、任务项目和外部消息渠道进入 P2。每个模块必须先确认业务负责人、数据边界和 PRD，不作为当前 V1.0 发布阻塞项。

## 6. 功能实施所需业务数据

进入开发前需由业务侧确认以下数据；未确认时只使用模拟数据，不写死为最终生产规则：

- 各类审批的办理时限、提前提醒时间、逾期升级人和审批人缺失时的处理方式；
- 请假类型、证明材料门槛、调休有效期及企业年假是否高于法定最低标准；
- 费用类别、差旅城市等级/职级标准、发票要求、预算维度和超预算策略；
- 采购金额档位、报价数量要求、采购负责人、验收角色及付款衔接方式；
- 印章清单、保管人、可外带范围、归还期限和高风险文件类别；
- 管理驾驶舱指标口径、统计周期及各角色可见范围；
- 用于 UAT 的脱敏部门、员工、上级、角色、合同、考勤和费用样本。

## 7. 开发与上线验收门槛

- 每项功能必须同步 PRD、页面、API、数据模型、权限点、审计事件和异常用例；
- 所有列表使用服务端分页和稳定倒序，所有业务记录都有详情页和状态轨迹；
