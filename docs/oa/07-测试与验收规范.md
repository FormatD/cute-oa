# OA V1.0 测试与验收规范

## 1. 测试层级

- 单元测试：状态机、权限判定、金额路由、工作日计算、编号和幂等。
- 集成测试：数据库事务、流程实例、消息事件、文件服务和外部适配器。
- API 测试：认证、租户隔离、分页、错误码、重复提交和版本冲突。
- 端到端测试：员工发起→审批→驳回/通过→通知→归档。
- 安全测试：越权、跨租户访问、上传文件、敏感数据和审计完整性。
- 会话安全测试：刷新令牌不落明文、轮换与重复使用检测、单设备/全设备撤销、改密/停用/角色变化失效、401 单次重试和退出后旧 JWT 拒绝。
- 性能测试：待办列表、提交接口、搜索、导出和高峰审批。

## 2. 必测场景

| 类别 | 场景 |
|---|---|
| 权限 | 普通员工不能审批他人单据；部门经理不能读取无权部门；跨租户 ID 不可访问 |
| 流程 | 金额/天数阈值前后路由不同；部门及下级部门、假别和优先级匹配确定；重叠范围发布被拒绝；审批人离职有替补；会签按规则结束 |
| 状态 | 草稿可编辑；审批中不可改核心字段；驳回可修改重提；完成不可重复付款 |
| 异常 | 重复点击提交、网络重试、通知失败、文件上传中断、数据库版本冲突 |
| 数据 | 金额两位小数、日期边界、空明细、超长文本、重复发票 |
| 审计 | 提交、审批、转办、导出、下载和权限变更均留痕 |
| 公告 | 草稿不可见；发布按时间倒序；确认已读幂等且按用户隔离；撤回/过期后员工不可见；并发版本受保护 |
| 出差 | 3 天阈值两侧路由；多段行程不重叠；同行人有效；有效出差防重叠；撤回/驳回/重提；附件、抄送和数据范围 |
| 出差报销 | 仅可关联本人已批准出差；关联状态和归属由服务端校验；跨 DbContext 保留外键和出差编号 |
| 人事档案 | 员工仅本人、上级管理链、HR 数据范围；档案字段与日期组合；组织循环；社会工龄同步；离职停号；事件只追加 |
| 考勤 | 员工/上级/HR 独立数据范围；班次版本；模拟补缺幂等；迟到/早退/缺卡/旷工/请假识别；申诉审核；原始异常保留；月报一致性；封账/解封权限、版本、审计与封账后变更拦截 |

## 3. 验收门禁

- P0 功能全部通过；不得有阻塞性或高风险安全缺陷。
- 核心流程端到端通过率 100%。
- 关键接口达到性能基线；失败请求有 requestId 可追踪。
- 租户隔离、权限校验、状态机和审计测试全部通过。
- 部署、备份、恢复、回滚和监控步骤可按文档执行。

## 4. 业务验收示例

**请假**：员工选择半天假并提交，系统按假别扣减余额；审批人通过后余额正式扣减，驳回后余额不变。

**报销**：提交 8,650 元报销，生成编号和流程实例；按金额路由到部门经理、财务经理和总经理；驳回后可修改重提且保留历史轨迹。

**出差**：提交 4 个日历天、多段行程的出差，直属上级通过后才出现总经理待办；全部通过后可在本人报销表单选择该出差，未批准出差不得关联。

**文件**：无文件权限用户不能通过猜测 URL 下载；新版本上传后旧版本可追溯；删除进入回收站并记录操作者。

**人事档案**：HR 将试用员工转为在职并填写转正日期，系统更新档案、同步社会工龄、追加转正事件；离职办结后账号和旧会话立即失效，但历史档案和业务记录仍可查询。

**考勤**：HR 生成当月模拟考勤后再次执行不覆盖已有数据；员工只能看到本人并对迟到记录申诉，HR 审核通过后状态变为“已修正”且原始迟到及审核意见仍可追溯，月度汇总同步更新。待审申诉存在时不能封账；封账后导入、生成、申诉和审核均被服务端拒绝；按版本解封后可以处理，重新封账保留完整审计。

**劳动合同**：员工可查看本人合同，直属上级不能仅凭管理链查看下属合同；HR 补充签署件后激活，日期重叠合同被拒绝，续签生成新版本且旧版本和事件永久保留。30 天预警后台派发一次，重复执行不产生重复通知，人工确认不改变合同状态。
