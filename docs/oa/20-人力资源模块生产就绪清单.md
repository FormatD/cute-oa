# 人力资源模块生产就绪清单

## 1. 当前结论

人事档案、员工生命周期办理清单、考勤基础和劳动合同台账已经达到“单公司生产候选”状态：业务数据持久化、服务端权限、敏感合同独立范围、数据库级乐观锁、附件关联、业务与站内通知同事务、审计、合同与员工事项预警幂等派发、存活/就绪检查、生产配置失败关闭和 PostgreSQL 双会话回归用例已具备。核心 HR 写操作可防止多应用实例静默覆盖；共享文件存储和登录限流等运维依赖仍限制当前推荐部署为单应用节点。

这不等于可以无条件直接上线。正式承载真实员工和签署合同前，必须完成本清单 P0 项；未完成的项目不能通过上线审批。

预发布和正式发布的责任人、配置、命令输出、UAT、ClamAV、备份、监控、镜像摘要及审批证据统一记录到《[人力资源模块生产上线验收记录模板](./24-生产上线验收记录模板.md)》，不得以本机验证结果替代目标环境签字。

## 3. 上线前 P0 门禁

- [ ] 通过环境变量注入至少 32 字节且与开发环境不同的 `Authentication__SigningKey`；生产密钥进入密钥管理系统，不写入镜像或仓库。
- [ ] 独立生成高熵 32 字节 Base64 `Authentication__MultiFactor__EncryptionKey` secret，禁止与 JWT 签名密钥复用；验证 HR、考勤、合同和系统管理员首次登录强制绑定 TOTP、恢复码只显示一次、管理员重置后全部会话失效。
- [ ] 设置 `ConnectionStrings__OaDatabase`，使用独立生产账号、最小权限、TLS 连接和连接池限制。
- [ ] 设置 `Cors__AllowedOrigins__0` 等明确的 HTTPS 前端来源，禁止通配来源配合凭据 Cookie。
- [ ] 设置明确的 `AllowedHosts` API 域名，禁止 `*`，并从外部域名验证错误 Host 被拒绝。
- [ ] 为 `Storage__Root` 挂载持久化加密卷，并验证应用用户只有所需目录权限；附件目录必须纳入备份。
- [ ] 保持 `DemoFeatures__AllowDataGeneration=false`，确认生产页面调用模拟数据接口时被服务端拒绝。
- [ ] 使用全新生产库或已完成真实组织迁移的数据库，确认不存在 `u-zhang`、`u-admin` 等演示身份，且每个账号都有经 HR 核对的唯一工号、真实入职日期、用工类型和人事状态；禁止依赖查询时自动建档。空库首次启动通过 `Bootstrap__AdminPassword` secret 及显式 `AdminEmployeeNumber/AdminHireDate` 创建一次性管理员；首次登录先完成强制改密再绑定 TOTP，并创建第二管理员；随后设置 `Bootstrap__Enabled=false`、轮换引导 secret，验证旧引导密码失败、正式密码与 MFA 登录成功、重启成功及 `PRODUCTION_ADMIN_BOOTSTRAPPED`/`INITIAL_PASSWORD_CHANGED` 审计。
- [ ] 抽样新员工和管理员重置账号，确认用户列表显示“待首次改密”，临时密码不产生 `auth_session`，弱密码/原临时密码/旧挑战/过期挑战均被拒绝，正式密码成功后状态清除且挑战不能重放；敏感权限账号继续进入 MFA 而不是绕过第二因子。
- [ ] 既有账号补档先用 `tools/Oa.HrProfileImport` 不带 `--apply` 预检，经 HR 核对行数和错误为零后再显式应用；保存脱敏输入文件摘要、操作人、输出和 `PERSONNEL_PROFILE_IMPORTED` 审计证据，完成后安全删除含工作联系方式的临时文件，并确认剩余缺档账号为 0。
- [ ] 配置 `PersonnelCases__CategoryAssignees__HR/FINANCE/IT/ADMIN` 为四类有效责任人，并确认 `PersonnelCaseAlerts__Enabled=true` 及扫描周期、临期和升级阈值；创建入职和离职办理单，验证职责分派、临期/逾期/升级通知及重复扫描去重；停用责任人前先完成改派并更新配置。
- [ ] 使用 `scripts/verify-backup-restore.sh` 在预发布环境执行两次数据库备份与一次隔离恢复演练，记录恢复点目标、恢复时间目标、备份加密/异地保管策略和责任人；本地 Compose 演练已通过，但不能替代预发布签字。
- [ ] 部署平台接入 `/health` 与 `/health/ready`，就绪失败停止流量；接入 5xx、登录失败、后台预警失败和磁盘容量告警。
- [ ] 使用真实组织副本完成 HR、员工、部门负责人、系统管理员四角色验收，并由人事/法务确认合同规则与提示文案。

- [ ] 在目标环境部署独立 ClamAV 服务，设置 `FileScanning__Mode=ClamAv`、主机、端口和超时；运行 `scripts/verify-clamav.sh` 等价场景，以安全样本、EICAR、停止和恢复扫描服务完成预发布验收并保存记录。本地官方镜像回归已通过，但不能替代目标环境病毒库、资源和告警签字。
- [ ] 配置 HTTPS，并通过 `ForwardedHeaders__KnownProxies__0` 等项注入每一跳可信反向代理 IP；从外部域名验证伪造转发头不能改变来源、HSTS、安全响应头及刷新 Cookie 的 `Secure` 属性。
- [ ] 构建、扫描并推送带不可变摘要的 API/Web 镜像，在预发布执行 `scripts/verify-containers.sh` 等价验证和实际域名冒烟；仓库模板与 API 本地镜像验证不能替代镜像仓库、安全扫描和目标主机签字。

## 4. 已知边界

- 当前租户仍固定为 `demo`，适合单公司独立部署，不适合多个公司共享同一实例。多租户上线前必须改造租户上下文和全链路隔离测试。
- 当前认证/权限目录在请求作用域加载公司用户与角色快照，业务花名册不会全量加载档案或逐行查询。该策略适合当前中小企业单公司规模；超大组织上线前应把管理链和数据范围进一步改为数据库递归查询或受版本控制的共享权限缓存，并重新做容量测试。
- 员工办理已支持显式职责配置、系统角色/权限解析、总负责人回退，以及自然日临期/逾期/升级提醒；当前尚无按部门条件细分同一职责、节假日工作日 SLA、多级升级链或外部消息渠道。
- 附件使用本地文件系统并已接入可插拔 ClamAV 扫描，但没有对象存储、在线预览、文件版本和自动生命周期；单节点挂载持久卷可用，横向扩容前必须抽象共享存储。病毒库更新、ClamAV 资源和告警由部署平台负责。
- 考勤尚无员工排班、外部打卡设备接入、员工电子签字确认和薪资结算接口；不可变封账月报、受审计解封及重新封账版本已具备。
- 合同模块提供规则提示，不自动作劳动法结论；电子签名、印章、工资和身份证等高敏字段不在当前范围。
- 当前 MFA 支持标准 TOTP 和一次性恢复码，尚无 WebAuthn/硬件安全密钥、企业 SSO 和 SIEM 对接；V1.0 不保存身份证号、银行卡等需要字段级加密/脱敏的高敏字段。应用内登录限流适合当前单节点部署，横向扩容前应改为 Redis 等共享计数或在可信入口网关实施等价策略。
- 后台预警当前只发送站内通知。短信、邮件或企业微信等外部渠道尚无事务型发件箱、渠道重试和失败补偿，接入前不得复用数据库事务内直发模式。

## 5. 推荐发布流程

1. 在预发布库运行全部迁移与 `bash scripts/verify.sh`、`bash scripts/verify-postgres.sh`。
2. 按《生产部署与文件安全运行手册》构建固定摘要镜像并完成容器、TLS、ClamAV 和外部域名冒烟。
3. 导入脱敏组织与少量合同，验证权限矩阵、附件下载、续签链和预警去重。
4. 备份生产库，维护窗口内运行增量迁移；不执行任何重置脚本。
5. 启动单实例，等待 `/health/ready` 成功后再切流；观察日志和资源 30 分钟。
6. 由 HR 完成关键用例签字，保留回滚版本和数据库备份；迁移含不可逆数据变更时禁止仅靠应用回滚。
