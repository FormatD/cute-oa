# 劳动合同台账与到期预警 PRD

> 实施状态：2026-09-01 已完成后端、前端、数据库迁移、后台预警派发、合同数据库并发保护和 PostgreSQL 自动化用例；生产环境仍须完成本文所链接的部署门禁。

## 1. 目标与法律边界

本模块在人事档案之上建立劳动合同台账、签署附件、历史版本和到期提醒，帮助 HR 发现未签、即将到期、试用期配置异常和可能需要无固定期限合同评估的员工。系统只提供记录、规则提示和流程留痕，不替代 HR、法务或劳动仲裁机构的个案判断。

规则基线来自现行《中华人民共和国劳动合同法》官方文本：劳动关系建立时应订立书面劳动合同；合同分固定期限、无固定期限和以完成一定工作任务为期限；合同必备条款见第十七条；试用期上限和“同一用人单位只能约定一次”见第十九条；应订立无固定期限合同的典型情形见第十四条。产品中的 90/60/30/7 天提醒属于企业管理策略，并非法定统一提前通知期限。

官方依据：

- [人力资源和社会保障部：《中华人民共和国劳动合同法》](https://www.mohrss.gov.cn/xxgk2020/fdzdgknr/zcfg/fl/202011/t20201102_394622_wap.html)
- [上海市人力资源和社会保障局：无固定期限劳动合同说明](https://rsj.sh.gov.cn/trdhy_17355/20210816/t0035_1401743.html)

## 2. 范围

### 2.1 V1 实现

- 员工合同台账、合同详情和历史合同；
- 固定期限、无固定期限、项目期限三种类型；
- 草稿、有效、到期、终止、被续签版本取代等状态；
- 合同编号、签订/生效/到期日期、试用期、工作地点、岗位、签署附件和备注；
- 新签、续签、变更、终止操作及只追加事件；
- 90/60/30/7 天到期分级提醒和工作台待处理数；
- 试用期法定上限提示、重复试用期拦截、未签书面合同风险提示；
- 连续工作满十年或连续固定期限合同次数达到二次时，显示“无固定期限合同评估”提示；
- Web 管理端和手机自适应，PostgreSQL 持久化和模拟合同数据。

### 2.2 暂不实现

- 电子签名、CA 证书、在线盖章和合同模板生成；
- 身份证号、家庭住址、工资、银行账号等高敏字段；
- 各地集体合同、特殊工种、退休年龄和经济补偿自动裁决；
- 自动解除/终止合同或自动改变员工账号状态；
- 与第三方电子签约、薪资或社保系统同步。

## 3. 角色与权限

| 角色 | 能力 |
| --- | --- |
| 员工 | 查看本人当前及历史合同基本信息和已授权附件 |
| 管理链上级 | 默认不查看下属合同正文与附件；仅在显式 Contract 数据范围授权后查看台账摘要 |
| HR/行政 | 按 Contract 数据范围创建、编辑、激活、续签、终止合同并处理预警 |
| 系统管理员 | 全公司范围与配置能力 |

新增 `CONTRACT_SCOPE_VIEW`、`CONTRACT_MANAGE` 和独立 `Contract` 数据范围。与人事档案不同，直属上级组织关系不自动授予劳动合同查看权；合同属于更敏感的人事数据。附件下载必须同时通过合同范围和附件关联校验。

## 4. 业务规则

### 4.1 合同类型与日期

- `FIXED_TERM` 固定期限：开始、结束日期必填，结束晚于开始。
- `OPEN_ENDED` 无固定期限：开始日期必填，结束日期必须为空。
- `PROJECT_BASED` 以完成一定任务为期限：项目/任务说明必填，可记录预计结束日期但不得作为自动终止依据。
- 签订日期不得晚于激活操作日；系统对“入职已超过一个月但无有效书面合同”显示高风险提醒，不自动推断法律后果。
- 同一员工有效合同日期不得重叠。服务端先执行友好校验，PostgreSQL 再以租户、员工和有效日期区间排斥约束作为最终防线；两个应用实例同时激活重叠合同时只能成功一个。
- 续签时创建新记录并把原合同标记为 `SUPERSEDED`，不覆盖原记录；同一原合同并发续签只能形成一条有效续签链。无结束日期的合同不执行“续签”，应进入合同变更或终止流程。

### 4.2 试用期校验

- 合同期限不足三个月或项目期限合同：不得设置试用期；
- 三个月以上不满一年：最多一个月；
- 一年以上不满三年：最多两个月；
- 三年以上固定期限或无固定期限：最多六个月；
- 同一员工在本租户任职期间只能记录一次试用期；历史合同已有试用期时，新合同禁止再次设置。

系统按自然日比较开始和结束日期，并把边界提示给 HR；最终合同文本和法务审核仍为准。

### 4.3 无固定期限评估提示

出现下列任一条件时标记 `OPEN_ENDED_REVIEW_REQUIRED`：

1. 人事档案显示员工在本单位连续工作满十年；
2. 历史中已有两次连续固定期限合同且进入续订场景；
3. HR 手工标记需要法务复核。

提示不会自动把合同类型改成无固定期限，也不会自动阻止合法的例外场景；HR 必须记录处理结论和说明。

### 4.4 状态与事件

状态：`DRAFT` → `ACTIVE` → `EXPIRED` / `TERMINATED`；续签后旧合同进入 `SUPERSEDED`。`EXPIRING` 为查询时根据到期日计算的展示状态，不写回主状态。

事件只追加：`CREATED`、`UPDATED`、`ACTIVATED`、`RENEWED_FROM`、`SUPERSEDED`、`TERMINATED`、`ALERT_ACKNOWLEDGED`。事件记录操作者、时间、原因和变更后快照。

## 5. 字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| contractNumber | 是 | 租户内唯一，创建后不可修改 |
| userId | 是 | 有效人事档案员工 |
| contractType | 是 | FIXED_TERM / OPEN_ENDED / PROJECT_BASED |
| signedDate | 激活时是 | 不晚于激活日 |
| startDate | 是 | 不早于合理历史边界 |
| endDate | 按类型 | 固定期限必填；无固定期限为空 |
| probationStart/End | 否 | 同时为空或同时有值；符合试用期上限 |
| workLocation | 是 | 默认取人事档案，可保留合同快照 |
| positionName | 是 | 默认取当前岗位名称，保存快照 |
| projectDescription | 项目期限时是 | 5–500 字 |
| attachments | 激活时是 | 至少一份已签署合同扫描件；最多 10 份 |
| renewalOfId | 续签时是 | 指向同员工上一份合同 |
| terminationDate/reason | 终止时是 | 不自动同步员工离职状态 |
| version | 是 | 乐观锁 |

## 6. 页面与接口

页面：

- `/hr/contracts`：到期风险卡片、筛选和分页合同台账；
- `/hr/contracts/:id`：合同详情、附件、规则提示和历史事件；
- 新建/编辑/续签/终止使用系统内弹窗或独立表单，不使用浏览器原生提示框。

接口：

- `GET/POST /api/v1/hr/contracts`
- `GET/PUT /api/v1/hr/contracts/{id}`
- `POST /api/v1/hr/contracts/{id}/activate`
- `POST /api/v1/hr/contracts/{id}/renew`
- `POST /api/v1/hr/contracts/{id}/terminate`
- `POST /api/v1/hr/contracts/{id}/alerts/acknowledge`
- `GET /api/v1/hr/contracts/alerts/summary`
- `POST /api/v1/hr/contracts/demo-data`

所有写接口要求幂等键。错误码：`CONTRACT_001` 字段/日期不合法、`CONTRACT_002` 合同日期重叠（HTTP 409）、`CONTRACT_003` 试用期规则不合法、`CONTRACT_004` 当前状态不允许操作、`CONTRACT_005` 缺少签署附件或附件归属错误、`CONCURRENCY_001` 陈旧版本（HTTP 409）。

## 7. 数据模型

| 表 | 关键字段与约束 |
| --- | --- |
| `employment_contract` | 租户 + 编号唯一；员工/状态/到期日索引；`Version` 数据库并发令牌；`btree_gist` 有效日期排斥约束；上一合同限制删除外键 |
| `employment_contract_event` | 合同、事件类型、操作者、原因、快照；只追加 |
| `contract_alert_ack` | 合同 + 提醒阈值唯一；确认人和时间 |
| `contract_alert_delivery` | 合同 + 接收人 + 提醒阈值唯一；保证后台任务和多次重启不重复派发 |

合同主表不保存身份证号、工资和家庭住址。已签合同附件仍可能含敏感信息，因此附件下载需要更严格的 Contract 权限，审计日志不得记录附件正文。

## 8. 验收标准

1. 员工只见本人；普通上级不能仅凭管理关系查看下属合同；HR 按 Contract 范围查看和维护。
2. 三类合同日期规则、同员工重叠保护、版本冲突和状态机均由服务端校验。
3. 四档试用期规则和“只能一次”自动化用例覆盖边界日期。
4. 激活必须有关联签署附件；附件越权下载被拒绝且下载留审计。
5. 续签创建新记录、旧记录不可覆盖，历史事件和附件跨重启保留。
6. 90/60/30/7 天预警按到期日准确分层，确认提醒不等于续签或终止。
7. 十年工龄和连续两次固定期限合同只触发法务评估提示，不自动作法律裁决。
8. 列表服务端分页、新记录在前；桌面端和 390px 手机端无整页横向溢出。
9. 两个独立服务实例并发激活重叠合同时仅一个成功；并发续签仅生成一条有效版本链；陈旧草稿更新返回 `CONCURRENCY_001`，状态、事件、审计和通知不重复。

## 9. 生产运行规则

- 到期预警后台任务默认每 360 分钟执行一次，可通过 `ContractAlerts__IntervalMinutes` 调整；同一合同、接收人和档位由数据库唯一约束保证只派发一次。
- 保留 `POST /api/v1/hr/contracts/demo-data` 演示能力。`DemoFeatures__AllowDataGeneration` 在基础配置中为 `false`，开发/演示环境可显式开启；非开发环境即使误配也由生产配置策略拒绝启动或由接口拒绝生成，正式数据不会在重启时被重置。
- `/health/ready` 同时检查 PostgreSQL 连接和附件目录读写能力；未就绪返回 HTTP 503。
- 部署前必须设置独立签名密钥、允许的前端来源、持久化附件卷、数据库备份和外部监控，详见 [人力资源模块生产就绪清单](./20-人力资源模块生产就绪清单.md)。
