# 中小企业 OA 需求与目标分析

## 1. 产品定位

面向中国大多数中小企业的轻量级企业管理中枢，重点连接“人、事、流程、文件、费用、合同、任务和数据”。

产品边界不是重做 ERP、CRM、财务或完整 HR，而是负责：谁来做、谁审批、流程怎么走、事项进展如何、企业信息在哪里；专业交易数据通过接口与其他系统协同。

## 2. 核心问题

1. 审批依赖纸张、微信或口头沟通，过程不可追踪。
2. 组织、岗位、审批人和数据权限缺乏统一规则。
3. 报销、采购、合同等事项缺乏费用和风险控制。
4. 制度、模板和业务知识分散，难以复用和检索。
5. 会议、任务和行动项无法形成闭环。
6. 管理层看不到审批效率、费用、合同和任务的整体情况。

## 3. 产品目标

### 业务目标

- 将高频行政和经营事项统一纳入线上流程。
- 让员工快速发起、处理和查询事项。
- 让管理者按角色看到待办、风险和关键指标。
- 通过标准化流程、权限和审计降低管理风险。
- 沉淀企业制度、模板和可检索知识。

### 技术目标

- 以组织权限、流程引擎、表单能力和消息中心为平台底座。
- 业务模块尽量配置化，降低新增审批事项的开发成本。
- 从第一天保留 API、Webhook、SSO、导入导出和第三方集成能力。
- 支持桌面端优先、移动审批可用，并保持安全、可审计和可扩展。

## 4. V1.0 建议范围

### P0：必须先做

- 登录、租户和基础用户体系
- 组织架构、岗位、角色、菜单/操作/API/数据权限
- 角色化工作台：待办、已办、我发起的、快捷入口
- 流程引擎：串行、会签/或签、条件路由、驳回、撤回、转办、委托、抄送、审批轨迹
- 表单能力：字段、校验、附件、版本、草稿与提交
- 消息中心：站内通知、待办提醒、超时提醒、已读状态
- 第一批验证业务：请假、出差、报销、采购申请、合同/用章申请
- 文件/知识中心基础能力：目录、权限、预览、版本、搜索、操作日志

### P1：V1.0 后续补齐

- 付款、借款、预算和费用分析
- 合同履约、收付款、到期和续签提醒
- 会议室、用车、办公用品、固定资产
- 任务、项目、里程碑、会议纪要和行动项
- 公告、制度发布、阅读确认
- 管理驾驶舱和流程绩效分析
- 企业微信、钉钉、飞书及财务/ERP/CRM 对接

### P2：暂不作为首发阻塞项

- AI 企业知识问答
- AI 审批提示、合同审查和问数
- 复杂 BI、自定义报表平台
- 完整 HR、ERP、CRM 和财务交易系统

## 5. 目标用户与关键价值

| 角色 | 主要任务 | 关键价值 |
|---|---|---|
| 普通员工 | 发起申请、报销、查制度、处理任务 | 少填重复信息，随时查看进度 |
| 部门负责人 | 审批、看团队任务和费用 | 快速决策，掌握团队风险 |
| 财务 | 审核费用、付款、预算和发票 | 费用可控、数据可追溯 |
| HR/行政 | 维护人员、假勤和行政资源 | 规则统一，减少手工台账 |
| 企业管理者 | 看经营事项、合同、费用和效率 | 用数据发现瓶颈和风险 |
| 系统管理员 | 维护组织、权限、流程和参数 | 配置优先，降低运维成本 |

## 6. 成功衡量建议

正式立项时补充基线和目标值，建议至少跟踪：

- 高频事项线上覆盖率
- 审批平均时长及 P95 时长
- 逾期待办数量
- 报销、采购和合同流程的可追溯率
- 制度/模板搜索成功率
- 移动端审批完成率
- 关键接口可用性、响应时间和错误率

## 7. 关键风险与待决策

以下事项不能由开发自行猜测，应在详细 PRD 中确认：

- 多租户是否首发，企业规模和并发目标是多少。
- 请假工作日、法定节假日、半天/小时假和撤销规则。
- 报销发票规则、金额分级、预算超额策略和付款边界。
- 合同是否需要法务、印章、电子签和履约台账。
- 数据权限是本人、所属部门、部门及下属还是自定义范围。
- 审批人不存在、离职、请假或组织变更时如何自动替补。
- 文件安全、敏感字段、审计保留周期和备份恢复目标。
- 首发移动形态：响应式网页、企业微信、钉钉还是小程序。

## 8. 开发启动判断

现在可以启动：项目骨架、认证、租户、组织、用户、岗位、角色、权限、字典、文件服务、日志、消息基础设施，以及流程引擎技术预研。

建议以“请假”验证简单流程，以“报销”验证复杂字段、条件审批、附件、预算和付款衔接。两者都能完整跑通，再扩展合同、采购和任务会议。
