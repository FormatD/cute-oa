# 采购申请模块 PRD

## 1. 产品目标

采购申请用于员工在发生采购前提交需求，通过多明细、预算金额、报价依据和金额分级审批控制支出；审批通过后由具备采购执行权限的人员登记下单信息，并由申请人或采购执行人员完成到货验收，形成“申请—审批—下单—验收”的可追溯闭环。

V1.0 面向中小企业通用办公采购，仅覆盖 Web 响应式界面。暂不实现预算科目余额占用、供应商准入评分、招投标、采购合同、库存台账、应付账款和付款；这些能力后续通过预算、供应商、合同、资产和财务模块扩展。

## 2. 角色与权限

| 角色 | 能力 |
|---|---|
| 员工 | 创建、编辑、提交、撤回和查看本人采购申请；对本人申请执行到货验收 |
| 部门负责人 | 按待办审批；按数据范围查看部门采购 |
| 财务经理 | 对中高金额采购进行预算合理性审批 |
| 总经理 | 对高金额采购进行最终审批 |
| 采购执行人员 | 按数据范围查看采购；对已批准申请登记下单；可执行到货验收 |
| 系统管理员 | 全公司查看、采购执行、流程与权限配置 |

新增权限：

- `PURCHASE_SCOPE_VIEW`：按角色数据范围查看他人采购申请；
- `PURCHASE_MANAGE`：登记采购下单并代为验收。

采购数据范围与请假、报销和出差一致，支持仅本人、本部门、本部门及下级部门、全公司。申请人、当前审批人和抄送人不受普通列表数据范围限制，可查看与自己直接相关的单据。

## 3. 页面范围

### 3.1 采购申请列表 `/purchase`

- 默认按创建时间倒序，服务端分页；
- 筛选：关键字、状态、申请人、需求日期范围；
- 列：申请单号、申请人、采购主题、需求日期、明细数量、预估总额、状态、操作；
- 支持发起采购和进入详情。

### 3.2 新建采购

基础字段：采购主题、采购用途、期望到货日期、建议供应商、抄送人、报价/需求附件。

采购明细支持 1–50 行：

- 品类：办公用品、IT设备、软件服务、行政物资、市场物料、生产物料、专业服务、其他；
- 物品/服务名称；
- 规格型号；
- 数量；
- 单位；
- 预估单价；
- 明细备注。

总额由服务端以“数量 × 预估单价”逐行四舍五入到两位小数后汇总，客户端金额仅作即时展示。

### 3.3 采购详情 `/purchase/:id`

- 显示基础信息、明细、预估总额、附件、流程版本、流程轨迹、审批任务；
- 审批中且所有节点均未处理时，申请人可撤回；
- 已批准时，有 `PURCHASE_MANAGE` 权限的人员可登记下单；
- 已下单时，申请人或有 `PURCHASE_MANAGE` 权限的人员可登记验收；
- 下单和验收记录一经保存不可直接修改，错误由后续冲销/变更能力处理。

### 3.4 审批中心

采购待办和已办与请假、报销、出差并列展示，支持同意、驳回和转办。驳回必须填写意见。

## 4. 字段与校验

### 4.1 申请

| 字段 | 规则 |
|---|---|
| 采购主题 | 必填，1–100 字符 |
| 采购用途 | 必填，1–500 字符 |
| 期望到货日期 | 必填，不早于申请创建日，最远不超过 365 天 |
| 建议供应商 | 可选，最多 100 字符，仅作建议，不代表最终成交供应商 |
| 采购明细 | 1–50 行，名称、数量、单位、预估单价必填 |
| 数量 | 大于 0，最多 4 位小数，单行不超过 1,000,000 |
| 预估单价 | 不小于 0，最多 2 位小数，单行不超过 10,000,000 元 |
| 预估总额 | 大于 0，不超过 100,000,000 元 |
| 附件 | 文件类型与 20 MB 限制沿用文件服务；5,000 元及以上至少 1 个报价或依据附件，50,000 元及以上至少 2 个附件 |
| 抄送人 | 可选，去重，必须为有效员工且不能包含申请人 |

### 4.2 下单记录

| 字段 | 规则 |
|---|---|
| 成交供应商 | 必填，1–100 字符 |
| 采购订单号 | 必填，1–64 字符；同租户唯一 |
| 实际采购金额 | 必填，大于 0，不超过批准预估总额的 110%；超出时应重新发起采购申请 |
| 下单日期 | 必填，不早于申请创建日期，不晚于当前日期 |
| 预计到货日期 | 必填，不早于下单日期 |
| 下单备注 | 可选，最多 500 字符 |
| 附件 | 可选，可上传订单、合同或确认函 |

### 4.3 验收记录

| 字段 | 规则 |
|---|---|
| 验收日期 | 必填，不早于下单日期，不晚于当前日期 |
| 验收结果 | V1.0 仅允许“全部通过”；部分到货和不合格退换货后续扩展 |
| 验收说明 | 必填，1–500 字符 |
| 验收附件 | 可选，可上传签收单、照片或服务交付物 |

## 5. 状态机

```text
Draft / Rejected / Withdrawn
        │ 编辑并提交
        ▼
    Approving ──驳回──> Rejected
        │
        ├──未处理前撤回──> Withdrawn
        │
        └──全部通过──> Approved ──登记下单──> Ordered ──验收通过──> Received
```

- 草稿、已驳回、已撤回可删除；
- 已批准、已下单、已验收不可撤回或删除；
- 已驳回可编辑后重新提交，保留旧流程实例与动作轨迹；
- 下单与验收不产生审批任务，但必须写审计日志与站内通知。

## 6. 默认审批规则

审批指标为预估总额：

| 预估总额 | 审批路径 |
|---|---|
| ≤ 5,000 元 | 直属上级 |
| 5,000–50,000 元 | 直属上级 → 财务经理 |
| > 50,000 元 | 直属上级 → 财务经理 → 总经理 |

默认流程编码 `PURCHASE_DEFAULT`。流程中心支持创建部门专属采购流程；V1.0 不按采购品类配置流程范围。审批节点去重规则沿用通用流程引擎。

## 7. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/purchase-requests` | 筛选与分页列表 |
| POST | `/api/v1/purchase-requests` | 创建草稿 |
| GET | `/api/v1/purchase-requests/{id}` | 详情 |
| PATCH | `/api/v1/purchase-requests/{id}?version=` | 编辑草稿/驳回单 |
| DELETE | `/api/v1/purchase-requests/{id}` | 删除可删除状态单据 |
| POST | `/api/v1/purchase-requests/{id}/submit` | 提交审批 |
| POST | `/api/v1/purchase-requests/{id}/withdraw` | 撤回 |
| POST | `/api/v1/purchase-requests/{id}/order` | 登记下单 |
| POST | `/api/v1/purchase-requests/{id}/receive` | 登记验收 |
| GET | `/api/v1/purchase-tasks/my` | 我的采购待办 |
| GET | `/api/v1/purchase-tasks/done` | 我的采购已办 |
| POST | `/api/v1/purchase-tasks/{id}/approve` | 同意 |
| POST | `/api/v1/purchase-tasks/{id}/reject` | 驳回 |
| POST | `/api/v1/purchase-tasks/{id}/transfer` | 转办 |

所有写接口必须支持幂等键；并发编辑使用版本号；服务端负责状态、身份、金额、附件归属和数据权限校验。

## 8. 错误码

| 错误码 | 含义 |
|---|---|
| `PURCHASE_001` | 采购明细或金额不合法 |
| `PURCHASE_002` | 报价附件数量不足 |
| `PURCHASE_003` | 下单信息不合法或订单号重复 |
| `PURCHASE_004` | 验收信息不合法 |
| `STATE_001` | 当前状态不允许操作 |
| `AUTH_002` | 无数据查看、审批或采购执行权限 |
| `CONCURRENCY_001` | 版本冲突 |

## 9. 验收用例

1. 4,000 元采购仅生成直属上级待办；审批后状态为已批准。
2. 20,000 元采购依次生成直属上级、财务经理待办；前序未完成时后序不可见、不可处理。
3. 80,000 元采购依次经过直属上级、财务经理和总经理。
4. 5,000 元及以上没有附件时提交失败；50,000 元及以上只有一个附件时提交失败。
5. 驳回后可编辑重提，旧流程实例永久保留。
6. 未处理的审批中申请可撤回；已有节点处理后不能撤回。
7. 无 `PURCHASE_MANAGE` 权限的非申请人不能登记下单；实际金额超过预估 110% 时拒绝。
8. 同租户采购订单号不能重复。
9. 申请人或采购执行人员可对已下单申请验收；其他用户被拒绝。
10. 列表按创建时间倒序分页，关键字可匹配单号、主题、用途、申请人和明细名称。
11. 直属上级、角色数据范围、当前审批人和抄送人的查看权限均由服务端验证。
12. PostgreSQL 重启后申请、审批轨迹、下单和验收记录仍存在；演示库不会因应用重启重置。

## 10. 非功能要求

- 关键状态迁移、金额和供应商字段变更写入审计日志；
- 通知失败不得回滚已完成的业务事务，后续可接入消息表重试；
- 列表查询应使用租户、申请人、状态、创建时间索引；
- JSON 明细仅用于 V1.0 快速交付，后续若接入订单、库存或报表，应迁移为独立采购明细表；
- 移动端优先保证列表查询、详情和审批；复杂多行编辑允许横向滚动但不能造成整页溢出。
