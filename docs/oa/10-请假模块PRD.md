# 请假模块 PRD

## 1. 目标与范围

请假模块使在职员工在线提交请假申请，由系统按工作日历和假别余额计算时长、匹配审批流程并留存全程记录。

V1.0 覆盖年假、事假、病假、调休；支持按天或半天请假。年假按中国法定最低标准和员工累计工作时间计算。小时假、销假、复杂排班和跨租户假期规则不纳入本期。

## 2. 角色和前置条件

- 员工：仅可创建和管理自己的请假申请。
- HR/行政：维护假别、余额和工作日历，可查看授权范围记录。
- 审批人：仅可处理分配给自己的请假审批任务。
- 申请人必须为在职状态；提交年假或调休前须有足够余额。

## 3. 页面与字段

### PAGE-LEAVE-002：新建请假

| 字段 | 类型 | 必填 | 默认值/规则 |
|---|---|---:|---|
| 申请人 | User | 是 | 当前用户，只读 |
| 所属部门 | OrgUnit | 是 | 当前主部门；有授权时可切换兼任部门 |
| 假别 | Select | 是 | 年假、事假、病假、调休；由字典维护 |
| 开始日期 | Date | 是 | 不早于当天前 30 天；不可晚于结束日期 |
| 开始时段 | Select | 是 | 全天、上午、下午 |
| 结束日期 | Date | 是 | 不早于开始日期 |
| 结束时段 | Select | 是 | 全天、上午、下午 |
| 请假时长 | Decimal | 是 | 服务端计算，只读，单位为天，最小 0.5 |
| 请假事由 | Textarea | 是 | 1–500 字符 |
| 证明附件 | File[] | 否 | 病假支持上传证明材料；是否认可由审批人审核 |
| 抄送人 | User[] | 否 | 最多 20 名同租户 ACTIVE 用户，不可选择自己；完成或撤回后生效 |

按钮：保存草稿、提交、取消。草稿保存不创建流程；提交成功后跳转详情页。

### PAGE-LEAVE-003：请假详情

展示单据编号、字段快照、时长计算明细、附件、当前状态和审批时间线。仅在 `DRAFT`、`REJECTED` 状态显示编辑/删除；仅在 `APPROVING` 且下一任务无人处理时显示撤回。

## 4. 业务规则

### 4.1 工作日计算

- 默认工作日为周一至周五，法定节假日不计入；国务院公布的调休工作日计入。HR 每年依据国务院办公厅节假日安排维护中国工作日历，系统允许补充企业特殊工作日。
- 全天记 1 天；上午或下午记 0.5 天。跨日请假按工作日和首尾时段累加。
- 开始日期/结束日期均为非工作日时，不允许提交；区间内非工作日自动不计入。
- 时长为 0 时不可提交。

### 4.2 假期余额

- 年假和调休为余额型假别；事假、病假不校验余额，但仍记录时长。
- 年假以员工累计工作时间计算，不限于本公司工龄。员工主数据维护“累计工作起始日”和“本单位入职日”；HR 应保存其核验依据。
- 员工连续工作满 12 个月后享受年假。默认法定最低额度为：累计工作满 1 年不足 10 年 5 天；满 10 年不足 20 年 10 天；满 20 年 15 天。企业可在租户假别配置中上浮，不得低于法定最低标准。
- 新入职且已满足累计工作时间条件的员工，当年年假按其在本单位剩余日历天数折算；不足 1 整天的部分不计。系统保留 HR 人工调整入口和调整审计。
- 余额按“员工 + 假别 + 自然年度”独立保存；年假与调休互不共用，跨年度年假/调休必须拆分申请，避免错扣年度额度。
- HR 人工调整保存相对于法定基线的增减值，粒度为 0.5 天；调整后总额不得低于已冻结与已使用额度，按版本执行乐观锁并写 `LEAVE_BALANCE_ADJUSTED` 审计。
- 提交时创建“冻结额度”，审批通过后扣减余额并释放冻结；驳回、撤回或删除草稿时释放冻结。
- 请假单状态、当前审批任务、流程动作、年度余额、业务审计和站内通知必须在同一数据库事务内提交；任一步并发冲突或写入失败均整体回滚，不得出现已提交但无任务、已审批但未扣减、已撤回但仍冻结或状态已变化但通知缺失等半成品。
- 请假单和年度余额分别使用数据库乐观版本。陈旧服务实例提交、审批、驳回、转办、撤回或调整余额时返回 `CONCURRENCY_001`，客户端刷新后重试，禁止后写覆盖先写。
- 同一用户、同一假别、时间区间重叠的 `SUBMITTED`、`APPROVING`、`APPROVED`、`COMPLETED` 单据不允许再次提交。
- 余额不足时返回 `LEAVE_001`，并显示可用余额、冻结余额与申请时长。

### 4.3 审批流程

默认流程：请假 3 天及以内由部门负责人审批；超过 3 天时，部门负责人审批后增加总经理审批。流程管理员可按部门、假别和天数配置版本化流程。部门范围包含下级部门，空部门/假别条件表示全公司/全部假别；多个流程同时匹配时按优先级、范围具体度、版本和发布时间选择。相同优先级和具体度的相交范围禁止同时发布。

审批人无法解析时，提交失败并返回 `FLOW_001`；不得创建无审批人的运行实例。直属上级和部门负责人为同一人时，系统自动去重，只创建一个任务。

## 5. 状态机

```text
DRAFT --提交--> APPROVING --通过--> APPROVED --完成动作--> COMPLETED
  ↑                  │                 
  └--驳回-- REJECTED ←┘
                    
APPROVING --撤回--> WITHDRAWN
```

V1.0 中审批通过即自动完成，因此 `APPROVED` 仅作为内部短暂状态，可直接转为 `COMPLETED`。状态为 `WITHDRAWN` 的单据只读，不可重新提交，需复制创建新单据。

## 6. 接口与错误码

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/leave-requests` | 创建草稿 |
| PATCH | `/api/v1/leave-requests/{id}` | 编辑草稿/已驳回单据 |
| POST | `/api/v1/leave-requests/{id}/submit` | 校验并提交 |
| POST | `/api/v1/leave-requests/{id}/withdraw` | 撤回申请 |
| GET | `/api/v1/leave-requests` | 列表查询 |
| GET | `/api/v1/leave-requests/{id}` | 详情与时间线 |
| GET | `/api/v1/leave-balances/me` | 当前用户假期余额 |
| GET | `/api/v1/hr/leave-balances/{userId}` | 本人或有 Personnel 管理权限的 HR 按假别、年度查询余额 |
| PUT | `/api/v1/hr/leave-balances/{userId}` | HR 按版本调整年度余额，保留法定基线和调整原因 |

业务错误码：`LEAVE_001` 余额不足或调整后低于已占用额度，`LEAVE_002` 时间区间重叠，`LEAVE_003` 时长计算为零，`LEAVE_004` 假别/年度/调整值无效或余额型请假跨年，`CONCURRENCY_001` 请假状态或年度余额已被其他操作更新。

## 7. 验收标准

- AC-LEAVE-001：员工选择周五全天至下周一全天请年假，周末不计入，系统计算为 2 天。
- AC-LEAVE-002：员工申请 0.5 天年假且余额为 0.5 天，提交后余额冻结 0.5 天；审批通过后可用余额减少 0.5 天。
- AC-LEAVE-003：员工提交与现有审批中请假重叠的时间区间，系统拒绝提交并提示重叠单据编号。
- AC-LEAVE-004：员工可为病假上传证明附件；审批人在详情页能预览附件并在不认可材料时驳回且填写意见。
- AC-LEAVE-005：员工撤回未被下一审批人处理的请假后，流程终止、冻结余额释放、审批人与抄送人收到通知。
- AC-LEAVE-006：无数据权限用户无法查看或下载其他员工的请假单和附件。
- AC-LEAVE-007：审批完成前抄送人不能查看单据；完成或撤回后进入抄送人的“待我阅读”，抄送人可查看详情和附件并独立标记已阅。
- AC-LEAVE-008：社会工龄不足 1 年为 0 天，满 1/10/20 年分别为 5/10/15 天；当年新入职按剩余日历天数向下取整。
- AC-LEAVE-009：年假与调休按年度隔离；跨年申请被要求拆分，上一年度已用量不占用新年度余额。
- AC-LEAVE-010：HR 可按 0.5 天调整年度额度；普通员工、过期版本及低于已占用额度的调整均被拒绝，审计可追溯。
- AC-LEAVE-011：两个独立服务实例读取同一余额版本后并发提交年假，首个成功、第二个返回 `CONCURRENCY_001`；第二张单据保持草稿、无审批任务且冻结额度不增加。
- AC-LEAVE-012：部门/假别专用流程优先于默认流程，父部门范围能覆盖下级部门，流程选择结果以编码和版本快照保存在单据与流程实例中。
- AC-LEAVE-013：数据库拒绝写入请假提交通知时，接口失败且请假单仍为草稿，不生成年度余额、审批任务、流程动作或提交审计；恢复通知写入后可重新提交。
