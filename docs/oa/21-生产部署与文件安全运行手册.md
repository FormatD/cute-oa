# 生产部署与文件安全运行手册

## 1. 适用范围

本手册适用于单公司、单应用实例的人力资源生产候选部署。正式承载员工档案、病假证明或劳动合同前，必须同时满足本文和《人力资源模块生产就绪清单》的 P0 门禁。

## 2. 必需配置

生产配置只通过部署平台的密钥或环境变量注入，不写回仓库：

| 环境变量 | 要求 |
| --- | --- |
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `Authentication__SigningKey` | 独立随机密钥，至少 32 字节 |
| `Authentication__MultiFactor__Enabled` | 必须为 `true` |
| `Authentication__MultiFactor__EncryptionKey` | 独立生成的高熵 32 字节 Base64 密钥；只通过 secret 文件注入，不与 JWT 签名密钥复用 |
| `Authentication__MultiFactor__RequiredPermissions` | 必须覆盖 `USER_MANAGE`、`PERSONNEL_EXPORT`、`PERSONNEL_MANAGE`、`ATTENDANCE_MANAGE`、`CONTRACT_MANAGE` |
| `Persistence__UsePostgreSql` | `true`；生产环境不允许内存模式 |
| `ConnectionStrings__OaDatabase` | PostgreSQL 非 `postgres` 账号，`SSL Mode=Require/VerifyCA/VerifyFull`，启用连接池且 `Maximum Pool Size` 为 1–200 |
| `Cors__AllowedOrigins__0` | 实际 HTTPS 前端源，不使用通配符 |
| `AllowedHosts` | 明确的 API 主机名；多个主机用分号分隔，不允许 `*` |
| `ForwardedHeaders__KnownProxies__0` | 直接连接应用的可信反向代理 IP；每一项必须是明确地址，不允许 `0.0.0.0`/`::` |
| `LoginProtection__Enabled` | 必须为 `true`；默认 300 秒内账号+IP 5 次、账号 15 次、IP 60 次 |
| `Storage__Root` | 已加密、持久化、纳入备份且仅应用账号可读写的绝对路径 |
| `DemoFeatures__AllowDataGeneration` | `false` |
| `Bootstrap__Enabled` | 仅空生产库首次启动设为 `true`；创建管理员后必须改为 `false` |
| `Bootstrap__AdminUserId` / `AdminName` | 一次性生产管理员身份；不得使用任何演示账号 ID |
| `Bootstrap__DepartmentId` / `DepartmentName` | 空库首次引导创建的管理部门 |
| `Bootstrap__AdminEmployeeNumber` | 一次性管理员真实且租户内唯一的工号，2–32 位字母、数字或横线 |
| `Bootstrap__AdminHireDate` | 一次性管理员真实入职日期，格式 `yyyy-MM-dd`，不能晚于当前日期后 90 天 |
| `Bootstrap__AdminPassword` | 仅通过独立 secret 文件注入的 12–128 位强密码，必须含大小写字母、数字和特殊字符 |
| `Authentication__PasswordChangeChallengeMinutes` | 临时密码验证后的改密挑战有效期，默认 10 分钟，服务端限制 5–30 分钟；仅最新挑战有效且只能消费一次 |
| `PersonnelCases__CategoryAssignees__HR/FINANCE/IT/ADMIN` | 有效职责负责人用户 ID；显式配置无效时办理单创建失败关闭 |
| `PersonnelCaseAlerts__Enabled` | 必须为 `true`；生产环境关闭员工事项提醒会拒绝启动 |
| `PersonnelCaseAlerts__IntervalMinutes` | 后台扫描周期，5–1440 分钟，默认 60 |
| `PersonnelCaseAlerts__DueSoonDays` | 临期提醒提前自然日数，0–30，默认 1 |
| `PersonnelCaseAlerts__EscalateAfterDays` | 逾期升级自然日数，1–90，默认 3 |
| `FlowSla__Enabled` | 必须为 `true`；生产环境关闭审批 SLA 扫描会拒绝启动 |
| `FlowSla__IntervalMinutes` | 审批任务临期、逾期和升级扫描周期，1–1440 分钟，默认 15 |
| `PersonnelExport__MaxRows` | 同步花名册导出上限，1–10000，默认 10000；超大组织改用后续异步受控导出 |
| `FileScanning__Mode` | `ClamAv`；非开发环境使用其他值会拒绝启动 |
| `FileScanning__ClamAv__Host` | ClamAV 内网服务名或地址 |
| `FileScanning__ClamAv__Port` | 默认 `3310`，不可暴露到公网 |
| `FileScanning__ClamAv__TimeoutSeconds` | 建议 `30`，合法范围 1–300 秒 |

应用先核验 PDF/图片文件头或 Office 容器结构，再使用 ClamAV `INSTREAM` 协议，因此不要求扫描服务访问附件持久卷。上传内容只在应用隔离文件中短暂停留，格式和扫描均安全后原子移动到正式文件名；扩展名伪装、感染、超时、连接失败或异常响应都不会创建 `file_object` 元数据。

人事档案、员工事项、考勤和劳动合同的“今天/本月”统一按北京时间（UTC+8）计算，不依赖容器本地时区；审计和技术时间戳仍以 UTC 保存。员工事项 SLA 当前使用北京时间自然日，不自动排除周末和法定节假日。

非开发环境在创建 Web 主机后、注册服务和监听端口前执行生产配置门禁。签名密钥、MFA 开关/加密密钥/敏感权限范围、数据库模式/TLS/账号/连接池、CORS、主机过滤、登录限流、可信代理、持久卷路径、模拟数据开关或一次性引导参数任一不合规时，进程会一次性列出全部原因并退出，不能降级为开发默认值继续运行。数据库迁移后还会执行生产身份门禁：演示账号、空库未启用引导、已有用户却仍启用引导、或没有有效 `USER_MANAGE` 管理员时均拒绝启动。

仓库提供 `compose.production.yml` 作为单节点生产候选模板。数据库使用外部托管 PostgreSQL，不把生产数据库打包进 Compose；API、Web 和 ClamAV 只通过内部网络互通。API 密钥和连接串通过 Docker secrets 文件注入，ASP.NET Core 使用 `Configuration__KeyPerFileDirectory=/run/secrets` 将文件名中的 `__` 映射为配置层级。TLS 证书和私钥同样只挂载为 secret，不写入环境文件、镜像或仓库。

## 3. 容器部署

### 3.1 产物与安全边界

| 产物 | 作用 | 运行约束 |
| --- | --- | --- |
| `backend/Oa.Api/Dockerfile` | 构建并运行 ASP.NET Core API | `app` 非 root 用户、只读根文件系统、仅附件卷可写、删除全部 Linux capabilities |
| `frontend/Dockerfile` | 构建 Vue 静态文件并运行 Nginx | `nginx` 非 root 用户、TLS 入口、同源 `/api/v1`、只读根文件系统 |
| `compose.production.yml` | 连接 Web、API、ClamAV 和外部 PostgreSQL | API 不发布宿主机端口；只有 Web 入口端口公开；内部服务使用固定地址 |
| `deploy/production.env.example` | 非敏感部署参数模板 | 复制到部署机后填写；其中只保存 secret 文件路径，不保存 secret 内容 |
| `scripts/verify-production-compose.sh` | 离线解析生产 Compose 并检查前端产物 | 使用临时占位 secret，不启动生产服务 |
| `scripts/verify-containers.sh` | 本地双容器 TLS/健康检查冒烟 | 只使用已构建的 `:local` 镜像和本地演示库，不重置数据库 |
| `scripts/verify-clamav.sh` | 官方 ClamAV 实际上传安全回归 | 使用独立测试库、临时容器/网络/卷，验证安全文件、EICAR、中断、审计和恢复后自动清理 |

生产前端默认使用当前 HTTPS 源下的 `/api/v1`，不再编译进开发地址 `127.0.0.1:5234`。Nginx 重建 `X-Forwarded-For` 为直接客户端地址，不接受客户端自行追加的来源链；API 只信任 Compose 中明确列出的 Web 容器地址。若部署网段与 `172.30.0.0/24` 冲突，必须同时修改 Compose 内网段、Web 固定地址和 `ForwardedHeaders__KnownProxies__0`，不能把可信代理扩大为任意网段。

### 3.2 首次预发布步骤

1. 复制 `deploy/production.env.example` 到部署机的受控环境文件，设置域名、端口、API/Web 与 ClamAV 镜像、ClamAV 平台和内存上限，四类员工办理职责负责人、员工事项提醒扫描/临期/升级阈值，以及六个 secret 文件绝对路径。
2. 分别生成至少 32 字节的随机 JWT 签名密钥、高熵 32 字节 MFA 加密密钥和一次性管理员强密码；写入三个独立 secret 文件。数据库连接 secret 使用最小权限账号和 `SSL Mode=VerifyFull`，并限制连接池。
3. 准备受信任 TLS 证书和私钥；将 secret 文件设为仅部署账号可读，不提交到 Git。
4. 运行 `docker compose --env-file <环境文件> -f compose.production.yml config`，确认最终配置没有 secret 内容、开发地址或通配 Host/CORS。
5. 运行 `docker compose --env-file <环境文件> -f compose.production.yml build`，由镜像仓库漏洞扫描后以不可变摘要发布；正式环境不得依赖可变 `latest` 标签。
6. 空生产库首次启动时设置 `OA_BOOTSTRAP_ENABLED=true`，同时填写真实 `OA_BOOTSTRAP_ADMIN_EMPLOYEE_NUMBER` 和 `OA_BOOTSTRAP_ADMIN_HIRE_DATE`，确认只创建一个管理员、一个管理部门、一份人事档案/初始事件和 `PRODUCTION_ADMIN_BOOTSTRAPPED` 审计；使用引导临时密码登录时不得创建业务会话，先通过十分钟单次挑战设置新的正式强密码，再绑定 TOTP，创建或导入真实组织与至少另一名管理员。已有账号缺少档案时进程会失败关闭，必须先用受控迁移补录真实字段，不能通过访问花名册自动生成。
7. 由第二名管理员核验引导管理员已完成正式改密和 MFA，确认旧引导密码及已消费挑战均无法使用；随后设置 `OA_BOOTSTRAP_ENABLED=false`，轮换引导密码 secret 后重启。已有真实组织的生产库从一开始就保持引导关闭。
8. Compose 会等待 ClamAV 内置 PING 健康检查通过后再启动 API，并等待 API 存活后启动 Web。只有外部 HTTPS `/health/ready` 返回 200 后才切入流量。
9. 执行本文文件安全验收、职责分派、角色 UAT 和备份恢复演练；考勤 UAT 同时核对 `attendance_month_snapshot` 的版本、行数、SHA-256、下载审计和历史锁迁移结果；保留镜像摘要、迁移版本、扫描病毒库版本、结果及签字。

`AddAttendanceMonthSnapshots` 迁移会为升级前处于封账状态的月份按当时考勤记录补建序号 1 快照。维护窗口执行迁移前必须先备份；执行后核对每个已锁月份至少有一个快照、最新快照行数与 JSON 数量一致且应用月报可读。该历史补建只能反映迁移时数据库中仍保留的记录，因此验收证据应记录迁移时间和来源备份编号。解封不会删除快照，应用版本回滚也不得手工删除该表或覆盖历史版本。

### 3.3 既有账号人事档案补录

只在隔离维护窗口使用项目内离线工具，不直接编写生产 SQL。先复制并填写 `deploy/templates/personnel-profile-import.example.json`；文件只允许包含本版本支持的工作信息，不得加入身份证、银行卡、家庭住址或健康信息。数据库连接串写入仅运行账号可读的 secret 文件，禁止作为命令参数或保存到 shell 历史。

```bash
export OA_HR_IMPORT_ACTOR_ID=具备PERSONNEL_MANAGE权限的生产管理员ID
export OA_HR_IMPORT_CONNECTION_FILE=/run/secrets/ConnectionStrings__OaDatabase
chmod 600 /secure/import/personnel-profiles.json

# 默认预检：校验权限、账号、唯一工号、字段和生命周期，零写入
dotnet run --project tools/Oa.HrProfileImport -- --file /secure/import/personnel-profiles.json

# HR 核对预检行数、输入文件摘要并完成变更审批后，显式整批应用
dotnet run --project tools/Oa.HrProfileImport -- --file /secure/import/personnel-profiles.json --apply
```

工具拒绝未应用迁移、无权限操作人、超过 10000 行、重复用户/工号、已有档案、错误日期和非法联系方式。`--apply` 在单一事务中写入整批档案、员工状态/精确工龄、初始事件和审计；失败整批回滚。成功输出必须显示“剩余缺档账号 0 个”，随后核对 `PERSONNEL_PROFILE_IMPORTED` 审计并安全删除临时输入文件。输入文件可能包含个人信息，不提交仓库、不进入普通日志或长期制品；验收记录只保存文件哈希、行数和受控存档引用。

本地构建后可运行 `bash scripts/verify-containers.sh`。该脚本创建独立临时 Docker 网络和自签名证书，验证 API/Web 镜像用户、只读运行、TLS 入口、安全响应头以及 `/health`、`/health/ready` 代理链，结束时清理自身创建的容器、匿名卷和网络。

再运行 `bash scripts/verify-clamav.sh` 验证真实扫描链。当前官方 `clamav/clamav:1.4` 镜像在本项目验证时只有 `linux/amd64` 清单，Apple Silicon 本地演练通过 `OA_CLAMAV_PLATFORM=linux/amd64` 使用模拟运行；目标主机必须在发布前确认架构兼容。Compose 对 ClamAV 删除全部默认 capabilities，仅恢复官方入口脚本启动所需的 `CHOWN`、`FOWNER`、`DAC_OVERRIDE`、`SETGID`、`SETUID`，并默认限制 4GB 内存。正式环境应把 `OA_CLAMAV_IMAGE` 设置为已扫描的不可变摘要，而不是长期使用可变标签。官方镜像与资源说明见 [ClamAV Docker 文档](https://docs.clamav.net/manual/Installing/Docker.html)。

## 4. HTTP 安全基线

应用为所有 API 响应统一设置以下响应头，生产环境另外启用 HSTS 和 HTTPS 重定向：

| 响应头 | 当前策略 |
| --- | --- |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `no-referrer` |
| `Permissions-Policy` | 禁用摄像头、麦克风和地理位置 |
| `Content-Security-Policy` | API 默认拒绝内容加载、表单提交和页面嵌入 |
| `Cross-Origin-Opener-Policy` | `same-origin` |
| `Cache-Control` | 登录、令牌和当前用户接口使用 `no-store` |

入口代理仍必须终止 TLS、只转发可信 Host，并按部署平台配置可信代理地址。应用只接受一跳且 `X-Forwarded-For`/`X-Forwarded-Proto` 数量对称的转发头；生产环境未提供明确可信代理地址时拒绝启动。上线验收需从外部 HTTPS 域名检查这些响应头、HSTS、重定向行为及刷新 Cookie 的 `Secure` 属性，不能只验证容器内 HTTP 地址。

登录入口使用固定窗口同时限制账号、来源 IP 和账号+IP 组合；账号键在内存中只保存不可逆 SHA-256 摘要。默认 300 秒内任一组合第 6 次、同账号第 16 次或同 IP 第 61 次请求返回 429/`AUTH_003`，并带整数秒 `Retry-After`；数据库仍独立执行连续 5 次密码错误锁定账号 15 分钟。失败计数在 PostgreSQL 内原子递增，多个请求同时校验错误密码也不会丢失计数；密码被并发重置或账号在校验期间被锁定时不签发会话。不存在、停用、空密码和已锁定账号仍执行一次同迭代数 PBKDF2 校验，HTTP 状态、文案与计算成本不暴露账号状态。该计数器有 10000 键上限并在容量不足时失败关闭，适用于当前单实例；多实例必须使用共享计数或入口网关限流，不能依赖各实例独立内存。

生产环境对用户管理、人事、考勤和合同维护权限账号强制 TOTP MFA。密码校验后只返回 5 分钟挑战，不签发业务 JWT；挑战连续 5 次错误、成功消费或到期后不可再次使用。TOTP 接受当前时间步及前后各一个 30 秒时间步，但数据库原子记录最后成功时间步，禁止动态码重放。10 个恢复码仅在绑定成功时返回一次，数据库只保存 SHA-256 摘要且每个只能原子消费一次。用户遗失验证器和恢复码时，必须由另一名系统管理员执行 MFA 重置；操作会清除密钥并撤销目标用户全部会话，敏感权限账号下次登录重新绑定。

MFA 加密密钥必须稳定备份到密钥管理系统。当前版本不支持无感轮换密文主密钥：计划轮换时应在维护窗口由管理员先重置已绑定账号、替换 secret 并重启应用，再由敏感权限用户逐一重新绑定；不得直接替换密钥后继续服务，否则既有 TOTP 密文无法解密并会失败关闭。

`AddMultiFactorAuthentication` 迁移会把升级前尚未撤销的登录会话统一标记为 `MFA_ROLLOUT`，避免旧刷新 Cookie 绕过 MFA。发布窗口应提前通知全员需要重新登录；该撤销不可由数据库 Down 迁移自动恢复，回滚应用也不会恢复旧会话。

## 5. 就绪与流量控制

- `/health` 仅表示进程存活。
- `/health/ready` 同时检查数据库连接、附件目录读写和扫描服务 `PING`。
- 生产环境只有 `database=ok`、`storage=ok`、`fileScanning=ok` 时才能接收流量。
- `fileScanning=unavailable` 时返回 HTTP 503；平台应停止新流量并告警，不应通过重启循环绕过。
- 开发环境会显示 `fileScanning=disabled`，不得把该状态作为生产验收通过证据。

## 6. 文件安全验收

在隔离的预发布租户执行以下三组用例，不使用真实员工材料：

1. 上传允许类型的安全 PDF，期望 201，能关联请假或合同并按权限下载。
2. 将 EICAR 官方测试内容放入隔离生成的 DOCX/ZIP 条目后上传，确保先通过允许类型结构校验再进入恶意扫描；期望 400/`FILE_006`，数据库无文件元数据，正式目录和隔离目录无残留，审计出现 `FILE_SCAN_BLOCKED`。
3. 停止 ClamAV 后上传安全样本，期望 503/`FILE_007`；数据库和目录无残留，审计出现 `FILE_SCAN_FAILED`，`/health/ready` 返回 503。恢复 ClamAV 后无需重启应用即可恢复就绪。

验收记录至少保存执行时间、应用版本、病毒库版本、响应码、审计记录、目录检查结果和责任人签字。EICAR 仅用于隔离测试环境，不通过邮件、IM 或真实业务附件流转。

### 6.1 HR 原子幂等验收

在预发布 API 已接入脱敏演示或专用验收租户时运行：

```bash
OA_VERIFY_API_BASE=https://oa-pre.example.com/api/v1 \
OA_VERIFY_HR_USER=预发布HR账号 \
OA_VERIFY_HR_PASSWORD_FILE=/run/secrets/oa-pre-hr-password \
bash scripts/verify-live-hr-idempotency.sh
```

脚本以当前默认班次原值执行一次保存，验证相同 `Idempotency-Key` 重放仅增加一次版本，并验证同键不同内容返回 `IDEMPOTENCY_002`。只允许使用专用验收租户和临时账号；不得把密码写入仓库、命令历史或验收报告，运行后应撤销临时会话并轮换临时密码。

## 7. 监控与日常运维

- 监控 `/health/ready`、429/`AUTH_003`、登录失败/锁定、`FILE_SCAN_FAILED`、`FILE_SCAN_BLOCKED`、扫描耗时、ClamAV 内存和病毒库更新时间。
- 监控 `PersonnelCaseAlertWorker` 异常日志、`PERSONNEL_TASK_ALERT_DISPATCHED` 每小时数量及待办逾期量；扫描周期内无派发日志不一定异常，但工作线程异常必须告警。
- 员工事项提醒通过 `(任务, 接收人, 类型)` 唯一记录去重。重启后抽查 `personnel_case_alert_delivery` 与 `notification` 数量一致；多实例部署前不得直接并行运行多个提醒工作线程。
- `FILE_SCAN_FAILED` 连续出现应立即停止附件上传流量并排查网络、资源和病毒库进程；不得临时改为 `Disabled`。
- `FILE_SCAN_BLOCKED` 应通知安全负责人核查上传人、时间和业务来源，不保留恶意文件副本。
- 每日确认病毒库更新成功；升级扫描服务先在预发布重跑安全样本和 EICAR 用例。
- 附件持久卷与数据库必须进入同一恢复演练，避免元数据和文件内容恢复点不一致。

## 8. 回滚原则

应用版本回滚不得关闭扫描门禁。新版本异常时可回滚应用，但必须保持 ClamAV 和持久卷；如果扫描服务本身不可用，应维持 503 和停止上传，恢复服务后再放流。任何人工清理只允许处理已确认的 `.upload` 隔离残留，不得批量删除正式附件。
