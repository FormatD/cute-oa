# 报销模块 PRD

## 1. 目标与范围

报销模块用于员工提交日常费用报销，由系统校验明细、发票和预算规则，按金额路由审批，并由财务确认付款和完成归档。

V1.0 覆盖单币种人民币、单据草稿、费用明细、合规票据/附件、审批和线下付款登记；发票 OCR、税务查验、借款冲销、复杂预算占用和银企直连为后续能力。

## 2. 角色与前置条件

- 员工：创建、编辑、提交、撤回自己的报销单。
- 部门负责人：审批职责范围内报销。
- 财务专员：审核、登记付款、退回补充资料。
- 财务经理与总经理：按金额规则审批。
- 申请人必须在职；费用日期不得晚于提交日期；申请人应具备对应费用中心/项目的数据权限。

## 3. 页面与字段

### PAGE-EXP-002：新建报销

| 字段 | 类型 | 必填 | 默认值/规则 |
|---|---|---:|---|
| 报销人 | User | 是 | 当前用户，只读 |
| 所属部门 | OrgUnit | 是 | 主部门；有授权时可选择兼任部门 |
| 报销日期 | Date | 是 | 默认当天，不可晚于当天 |
| 费用归属项目 | Project | 否 | 按数据权限筛选；V1.0 可为空 |
| 收款账户名称 | Text | 是 | 1–100 字符，默认员工账户信息 |
| 收款账号 | Text | 是 | 6–64 字符，脱敏显示和审计 |
| 开户行 | Text | 条件必填 | 非企业统一付款账户时必填 |
| 报销说明 | Textarea | 否 | 最多 500 字符 |
| 费用明细 | ExpenseItem[] | 是 | 至少 1 条；总额由明细汇总，只读 |
| 发票附件 | File[] | 条件必填 | 按费用类别要求；至少关联到一条明细 |
| 抄送人 | User[] | 否 | 最多 20 名同租户 ACTIVE 用户，不可选择自己；审批完成或撤回后生效 |

费用明细字段：费用日期、费用类别、金额、费用说明、项目、票据号、附件。金额 `>0` 且最多两位小数；费用日期不得晚于报销日期且不得早于报销日期前 180 天。

按钮：保存草稿、提交、删除草稿。明细支持新增、编辑、删除；提交后不可直接修改。

### PAGE-EXP-003：报销详情

展示单据摘要、明细、发票、预算提示、收款账户脱敏信息、付款信息和审批时间线。财务可在 `APPROVED` 状态执行“登记付款”；付款操作要求填写付款日期、付款方式、付款流水号和实付金额。

## 4. 业务规则

### 4.1 明细与发票

- 至少一条费用明细，单据总额为所有明细金额之和，服务端重新计算。
- 默认费用类别：交通、住宿、餐饮招待、办公、通讯、培训、其他；字典可维护是否强制票据、单笔限额与审批附加条件。
- V1.0 默认所有费用类别均须关联有效票据或其他合规凭证；交通类可上传电子行程单/车票等凭证。票据号为有发票时必填，其他凭证记录凭证编号或说明。
- 同一租户下已在 `APPROVING`、`APPROVED`、`COMPLETED` 单据中使用的同类票据号不可再次提交。
- 发票附件不等于文件存在：文件必须已完成安全校验且属于当前租户。

### 4.2 预算

V1.0 提供预算校验开关。预算关闭时只记录费用类别和项目；预算开启且超预算时：默认允许提交并添加“超预算”标记，额外进入财务经理审批。禁止提交策略可由租户参数启用。

### 4.3 审批与付款

首发采用以下通用审批规则，所有阈值、审批角色和超预算加签均由流程定义配置，后续不需要改代码：

| 单据总额 | 审批路径 |
|---:|---|
| ≤ 1,000 元 | 部门负责人 → 财务专员 |
| 1,000–5,000 元 | 部门负责人 → 财务专员 → 财务经理 |
| > 5,000 元 | 部门负责人 → 财务专员 → 财务经理 → 总经理 |

金额取提交时服务端计算的总额；已启动流程不因后续阈值调整而改变路径。审批通过后进入待付款状态，由具有 `EXPENSE_PAY` 权限的用户登记线下付款；付款登记使用系统内表单，必须填写付款日期、付款方式、付款流水号、实付金额并上传付款凭证。凭证必须属于当前付款人，付款后按报销详情数据权限提供下载并记录审计。实付金额必须等于申请金额，一张单据仅允许一次付款；部分付款、合并付款、作废付款不纳入 V1.0。

驳回到申请人后，申请人可修改并重新提交；重新提交产生新的流程实例，旧实例和意见永久保留。

## 5. 状态机与操作矩阵

```text
DRAFT → APPROVING → APPROVED → PAYING → COMPLETED
            │            
            ├→ REJECTED → DRAFT
            └→ WITHDRAWN
```

| 状态 | 申请人 | 审批人 | 财务 |
|---|---|---|---|
| DRAFT | 编辑、删除、提交 | — | — |
| APPROVING | 撤回（满足条件） | 同意、驳回、转办 | 审批（如为当前任务） |
| REJECTED | 编辑、删除、重新提交 | — | — |
| APPROVED | 查看 | 查看 | 确认待付款 |
| PAYING | 查看 | 查看 | 登记付款 |
| COMPLETED | 查看、导出 | 查看 | 查看、导出 |

## 6. 接口与错误码

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/expense-claims` | 创建草稿 |
| PATCH | `/api/v1/expense-claims/{id}` | 编辑草稿/已驳回单据 |
| POST | `/api/v1/expense-claims/{id}/submit` | 校验并提交 |
| POST | `/api/v1/expense-claims/{id}/withdraw` | 撤回申请 |
| POST | `/api/v1/expense-claims/{id}/payment` | 财务登记付款 |
| GET | `/api/v1/expense-claims` | 列表查询 |
| GET | `/api/v1/expense-claims/{id}` | 详情与时间线 |

业务错误码：`EXP_001` 无费用明细，`EXP_002` 发票/附件缺失，`EXP_003` 重复发票号，`EXP_004` 费用日期超限，`EXP_005` 实付金额不一致，`EXP_006` 超预算禁止提交。

## 7. 验收标准

- AC-EXP-001：员工提交含两条明细、总额 8,650 元的报销单，系统生成唯一编号、创建流程实例，并依次生成部门负责人、财务专员、财务经理、总经理任务。
- AC-EXP-002：费用明细未关联有效票据/凭证时，系统不允许提交并定位到对应明细；填写发票的明细未填写发票号时同样不允许提交。
- AC-EXP-003：同一发票号已在有效报销单中使用时，系统拒绝再次提交，且不创建新的流程实例。
- AC-EXP-004：预算开启且超预算时，单据被标记超预算并额外路由至财务经理；禁止提交策略启用时，系统直接拒绝提交。
- AC-EXP-005：审批人驳回后，申请人修改金额重新提交，系统保留旧流程轨迹并按照新金额重新匹配流程。
- AC-EXP-006：财务登记付款时，实付金额不等于申请金额，系统拒绝完成付款；填写有效流水号和一致金额后，单据进入 `COMPLETED`。
- AC-EXP-007：无付款权限的用户无法调用付款接口，即使能够查看该报销详情。
- AC-EXP-008：审批完成前抄送人无查看权限；进入 `APPROVED` 或申请撤回后，抄送人收到待阅读事项并可只读查看报销详情和附件。
- AC-EXP-009：付款人不能引用其他用户上传的文件作为付款凭证；有效付款凭证、方式和流水号在重启后仍可从报销详情读取，并仅向有该单据数据权限的用户开放下载。
