# 考勤管理模块 PRD

## 1. 目标与边界

考勤管理在既有中国工作日历、组织关系、人事档案和请假数据之上，建立员工班次、打卡记录、异常识别、异常申诉、月度汇总和月度封账。第一版服务于 Web 管理端并适配手机浏览器，使用可重复生成的模拟打卡数据，不接入门禁、定位或第三方考勤机。

“工作日历”只回答某天是否应工作；“考勤管理”回答某位员工当天应按什么班次出勤、实际何时打卡、是否异常以及异常如何闭环。两者在产品和数据模型中保持独立。

## 2. 角色与数据范围

| 角色 | 能力 |
| --- | --- |
| 员工 | 查看本人记录和月报；对本人异常记录提交申诉及附件 |
| 管理链上级 | 查看全部下级的记录和月报，不可修改原始打卡 |
| HR/行政 | 按角色数据范围查看考勤；维护班次；导入/生成模拟打卡；审核申诉；仅公司范围可执行全公司封账、解封和快照下载 |
| 系统管理员 | 全公司范围和全部维护能力 |

新增 `ATTENDANCE_SCOPE_VIEW` 与 `ATTENDANCE_MANAGE`。角色按 `Attendance` 单独配置 `SELF`、`DEPARTMENT`、`DEPARTMENT_AND_CHILDREN`、`COMPANY`，不能复用人事档案或请假范围来放大权限。

## 3. 功能需求

### 3.1 班次规则

- 班次包含编码、名称、上班时间、下班时间、休息分钟数、迟到宽限、早退宽限、启停状态和版本。
- 至少保留一个启用的默认班次；第一版全部员工使用默认班次，后续扩展排班与员工班次分配。
- 班次修改只影响后续导入/生成的记录，历史记录保存当时的班次快照。

### 3.2 打卡记录

- HR 可批量导入员工、日期、上班打卡、下班打卡；同一员工同一日期唯一，重复导入更新记录并增加版本。
- 模拟数据生成只补齐缺失记录，不覆盖人工导入、已申诉或既有模拟记录，也不重置数据库。
- 系统结合中国工作日历、已完成请假和班次规则识别：正常、迟到、早退、迟到且早退、缺卡、旷工、请假、休息日、已修正。
- 原始打卡时间、来源和原始异常状态必须保留，不能因申诉通过而删除证据。

### 3.3 异常申诉

- 员工只能对本人异常记录申诉，同一记录同时只允许一个待审核申诉。
- 原因必填，附件可选；附件沿用文件中心归属和下载授权。
- HR 审核必须填写意见。通过后记录标为“已修正”并保留原始状态；驳回不改变异常状态。
- 申诉状态作为数据库并发条件；两个审核实例同时处理同一申诉时只有首个成功，陈旧审核返回 `CONCURRENCY_001`。
- 数据库部分唯一索引保证同一考勤记录最多存在一个待审核申诉，跨实例重复提交返回 `ATTENDANCE_002`。
- 提交、通过、驳回均写审计日志并通知员工。

### 3.4 月度汇总

- 按员工和月份统计应出勤、实际出勤、正常、迟到、早退、缺卡、旷工、请假、已修正、待审申诉和工作分钟数。
- 列表和汇总使用同一数据范围；员工仅见本人，上级见管理链下属，HR 按 `Attendance` 范围查看。
- 所有列表服务端分页，按日期和更新时间倒序，新记录在前。
- 只有具备 `ATTENDANCE_MANAGE` 且 Attendance 数据范围为 `COMPANY` 的管理员，在当月不存在待审核申诉且已有考勤记录时可以封账；部门范围管理员和普通员工不能影响全公司封账状态。
- 封账在同一事务中追加完整月度汇总快照、序号、行数和 SHA-256。封账后导入、模拟生成、员工申诉和 HR 审核均被服务端拒绝；详情继续只读，月报从已校验快照读取并按调用人的可见员工范围过滤，不重新计算实时结果。
- 公司范围考勤管理员可下载当前封账版本的安全 UTF-8 BOM CSV，下载动作写审计；快照缺失、格式错误、行数或哈希不一致时查看和下载均失败关闭。
- 解封必须填写原因并携带当前版本，过期版本被拒绝；历史快照不删除，重新封账生成下一序号并保留完整封账/解封审计轨迹。

## 4. 数据模型

| 表 | 说明 | 关键约束 |
| --- | --- | --- |
| `attendance_shift` | 班次规则 | 租户内编码唯一；`Version` 数据库并发令牌 |
| `attendance_record` | 每日考勤与班次快照 | 租户 + 用户 + 日期唯一；`Version` 数据库并发令牌 |
| `attendance_appeal` | 异常申诉与审核结果 | 关联考勤记录；`Status` 数据库并发令牌；每条记录最多一个待审申诉 |
| `attendance_month_lock` | 月度封账状态 | 租户 + 月份唯一；`Version` 数据库并发令牌；封账/解封人、时间和原因 |
| `attendance_month_snapshot` | 不可变封账月报 | 租户 + 月份 + 序号唯一；完整 JSON、SHA-256、行数、操作者和原因只追加 |

## 5. 接口

- `GET /api/v1/attendance/shifts`
- `PUT /api/v1/attendance/shifts/{id}`
- `GET /api/v1/attendance/records`
- `GET /api/v1/attendance/records/{id}`
- `POST /api/v1/attendance/import`
- `POST /api/v1/attendance/demo-data/{month}`
- `POST /api/v1/attendance/records/{id}/appeals`
- `POST /api/v1/attendance/appeals/{id}/review`
- `GET /api/v1/attendance/monthly-summary`
- `GET /api/v1/attendance/month-lock`
- `POST /api/v1/attendance/month-locks/{month}/lock`
- `POST /api/v1/attendance/month-locks/{month}/unlock`
- `GET /api/v1/attendance/month-locks/{month}/snapshot`

所有写接口要求幂等键。错误码使用 `ATTENDANCE_001`（字段/时间不合法）、`ATTENDANCE_002`（重复待审申诉）、`ATTENDANCE_003`（记录状态不允许操作）、`ATTENDANCE_004`（月份已封账）、`ATTENDANCE_005`（仍有待审申诉）、`ATTENDANCE_SNAPSHOT_001`（已封账但快照缺失）、`ATTENDANCE_SNAPSHOT_002`（快照完整性失败）及通用权限、并发错误码。

## 6. 验收标准

1. 员工只能看到本人，上级能看到管理链下属，HR 能按独立数据范围查看公司记录。
2. 默认班次可维护，非法时间和旧版本更新被拒绝。
3. 批量导入能新增和更新，工作日、请假、迟到、早退、缺卡和旷工识别正确。
4. 模拟数据生成幂等且不覆盖已有数据，正常重启不重置。
5. 员工申诉、HR 审核、附件授权、通知和审计形成闭环，审批通过保留原始异常。
6. 月度汇总与明细一致；桌面端和 390px 手机端可完成查看与申诉，无整页横向溢出。
7. 待审申诉阻止封账；只有公司范围考勤管理员可以封账/解封；封账后所有考勤变更被拒绝，月报只读取已校验快照；下载安全 CSV 写审计；解封和重新封账经过版本校验并生成递增快照版本。
8. 两个独立应用实例同时更新班次、同日考勤、同一申诉或同月封账时只有首个成功，陈旧操作统一返回 `CONCURRENCY_001`，不得产生重复审核、重复待审申诉或静默覆盖。
9. 升级前已封账月份自动补建版本 1；快照 JSON、行数或哈希被修改时查看和下载均失败关闭，不得回退实时重算。

## 7. 后续范围

- 员工班次分配、轮班排班、跨日班次与弹性工时；
- 第三方考勤机、门禁、企业微信/钉钉打卡接入；
- 加班申请、调休自动入账与薪资系统对接；
- 电子考勤签字确认、薪资结算批次关联，以及经审批的历史快照更正/冲销流程。
