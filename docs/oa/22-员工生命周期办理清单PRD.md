# 员工生命周期办理清单 PRD

> 实施状态：2026-09-01 已完成数据库迁移、后端服务、Vue 页面、临期/逾期/升级提醒和 PostgreSQL 集成用例。生产上线仍须完成《人力资源模块生产就绪清单》的外部环境门禁。

## 1. 目标与范围

将入职、转正、调动和离职从单一档案状态变更扩展为可分派、可追踪、可审计的标准办理过程，避免只改员工状态而遗漏账号、资产、财务、合同或工作交接。

V1.0 支持单公司、单主岗位、跨职能负责人自动解析和站内通知，不包含招聘候选人、电子签名、薪资结算或企业微信。

## 2. 角色与权限

| 角色 | 能力 |
| --- | --- |
| 员工本人 | 查看本人办理单；完成分配给自己的待办 |
| 直属上级 | 在管理链数据范围内查看；完成分配给自己的交接或评估任务 |
| 任务负责人 | 查看包含本人任务的办理单；只能完成本人尚未处理的任务 |
| HR/行政 | 在 `Personnel` 数据范围内创建、改派、调整截止日、完成、留因豁免、重开、办结或取消 |
| 系统管理员 | 按所授 `PERSONNEL_MANAGE` 与 `Personnel` 范围执行相同能力 |

页面隐藏不作为授权依据；列表、详情和每个修改接口都必须在服务端重新校验权限。

## 3. 办理类型与标准模板

### 3.1 入职 `ONBOARDING`

员工资料建档、劳动合同、账号开通、设备与门禁、制度培训、直属上级入职计划，共 6 项。

### 3.2 转正 `REGULARIZATION`

员工转正总结、直属上级评估、HR 决策归档、合同及人事信息核对，共 4 项。

### 3.3 调动 `TRANSFER`

调动依据归档、原岗位交接、系统权限调整、资产/门禁调整、新岗位职责确认，共 5 项。

### 3.4 离职 `OFFBOARDING`

工作交接、资产归还、财务结清、账号关闭、合同文件归档、员工材料确认，共 6 项；员工材料确认可由 HR 留因豁免，其余任务必须完成或由 HR 明确留因豁免。

员工和直属上级任务分别分派给员工本人和当前直属上级；没有有效上级时回退给办理负责人。HR、财务、IT、行政任务按以下顺序解析：生产配置中的职责负责人 ID、系统角色优先级、对应服务端权限、办理总负责人。生产配置已填写但用户不存在或停用时失败关闭并返回 `PERSONNEL_CASE_004`，不得静默回退或留下半成品办理单。职责映射使用 `PersonnelCases__CategoryAssignees__HR/FINANCE/IT/ADMIN` 配置，人员变化后应先更新配置再停用原负责人。

## 4. 状态与业务规则

办理单状态：`OPEN → COMPLETED` 或 `OPEN → CANCELLED`。结束后不可修改任务、重复办结或重复取消。

任务状态：`PENDING → COMPLETED/WAIVED`；HR 可将已处理任务重开为 `PENDING`。

- 同一租户、员工、类型和生效日期只允许一张办理单；
- 办理单和每项任务分别使用乐观版本，陈旧版本返回 `CONCURRENCY_001`；
- 非 HR 任务负责人不能改派、修改截止日、豁免或重开；
- 完成说明至少 2 个字符，豁免原因至少 5 个字符；
- 仍有 `PENDING` 任务时返回 `PERSONNEL_CASE_002`，禁止办结；
- 列表按更新时间、创建时间倒序并由服务端分页；逾期仅对未结束办理单中的待办任务计算；
- 创建、任务处理、办结和取消全部写 `PersonnelCase` 审计日志；新任务改派和办理单完成发送站内通知；
- 后台任务默认每 60 分钟扫描一次：截止日前 1 天（含当天）向有效任务负责人发送 `DUE_SOON`；逾期至少 1 天向任务负责人和办理负责人发送 `OVERDUE`；逾期至少 3 天向二者及对该员工有数据权限的 `PERSONNEL_MANAGE` 管理人员发送 `ESCALATED`；
- 提醒阈值通过 `PersonnelCaseAlerts__DueSoonDays`、`EscalateAfterDays` 和 `IntervalMinutes` 配置。业务日期固定按北京时间（UTC+8）计算，不受容器 UTC 时区影响；当前按自然日计算，不跳过周末和法定节假日；
- 同一任务、接收人和提醒类型只允许一条派发记录。后台任务重复执行或应用重启不得重复发送同档提醒，每次实际派发写 `PERSONNEL_TASK_ALERT_DISPATCHED` 审计。

## 5. 生命周期自动衔接与离职门禁

- 档案从试用转为在职时自动生成同生效日期的转正办理单；
- 部门、岗位或直属上级变化时自动生成同生效日期的调动办理单；
- 进入 `OFFBOARDING` 必须填写计划离职日期和原因，并按计划离职日期生成离职办理单；
- 进入 `TERMINATED` 必须满足：上一状态为 `OFFBOARDING`，且存在同员工、类型为 `OFFBOARDING`、生效日期等于本次计划离职日期、状态为 `COMPLETED` 的办理单；
- 历史上其他日期的已完成离职单不能满足本次离职门禁；
- 门禁通过后，档案更新、账号停用、事件、办理单自动生成等数据库写入使用事务，失败不得留下半成品。

入职办理单当前由 HR 手工创建；后续招聘录用模块负责自动生成。

## 6. 页面与接口

页面：

- `/hr/personnel-cases`：关键字、类型、状态、分配给我筛选，服务端分页，新建办理单；
- `/hr/personnel-cases/:id`：办理信息、完成进度、逾期数、任务表、任务处理、办结和取消；
- 员工档案详情提供“查看办理清单”入口并携带员工筛选参数。

接口：

- `GET/POST /api/v1/hr/personnel-cases`
- `GET /api/v1/hr/personnel-cases/{id}`
- `PUT /api/v1/hr/personnel-cases/{id}/tasks/{taskId}`
- `POST /api/v1/hr/personnel-cases/{id}/complete`
- `POST /api/v1/hr/personnel-cases/{id}/cancel`

## 7. 数据与索引

`personnel_case` 保存员工和组织快照、类型、生效日期、负责人、状态、办结/取消信息与版本；`personnel_case_task` 保存任务模板编码、分类、必办标识、负责人、截止日、完成信息和独立版本；`personnel_case_alert_delivery` 保存任务、接收人、提醒类型和派发时间。

关键唯一约束为 `tenant_id + number`、`tenant_id + user_id + type + effective_date`、`personnel_case_id + code` 和 `personnel_case_task_id + recipient_id + alert_type`；任务删除随办理单级联，员工删除受限，历史办理记录不得物理删除。

## 8. 错误码

| 错误码 | 含义 |
| --- | --- |
| `PERSONNEL_CASE_001` | 类型、日期、负责人、任务状态或说明不合法 |
| `PERSONNEL_CASE_002` | 存在未处理任务，不能办结 |
| `PERSONNEL_CASE_003` | 离职状态、计划日期或完成清单不满足停号门禁 |
| `PERSONNEL_CASE_004` | 生产职责负责人配置不存在或已停用 |
| `AUTH_002` | 无数据查看或修改权限 |
| `CONCURRENCY_001` | 办理单或任务版本陈旧 |
| `DUPLICATE_001` | 同员工、类型和日期办理单已存在 |

## 9. 验收用例

1. HR 创建入职办理单自动生成 6 项标准任务，同员工同类型同日期重复创建被拒绝。
2. 员工本人可查看办理单，只能完成分配给自己的待办；无关员工无法查看。
3. HR 可改派、调整截止日、完成、留因豁免或重开；陈旧任务版本被拒绝。
4. 存在待办任务时不能办结；全部完成或豁免后才可办结，结束后不可修改。
5. 试用转正、组织调动和进入离职办理分别自动生成对应标准清单。
6. 进入离职办理但缺少计划离职日期或原因时返回 `PERSONNEL_003`。
7. 完成历史其他日期离职单后，本次计划日期离职仍返回 `PERSONNEL_CASE_003`。
8. 完成本次计划日期离职单后允许办结离职，账号立即停用且既有会话撤销。
9. 办理单、任务状态和审计记录跨 DbContext、应用重启和增量迁移完整保留。
10. HR、财务、IT、行政任务按职责自动分派；显式配置可覆盖角色解析，配置指向停用用户时创建失败且数据库无半成品。
11. 临期日首次执行只提醒任务负责人，重复执行不新增记录；逾期 1 天首次执行提醒任务负责人和办理负责人并去重。
12. 逾期 3 天首次执行升级给办理负责人及具备该员工数据权限的 HR 管理人员；通知、唯一派发记录和系统审计跨 DbContext 保留。
